# 世界模型评测：现状、指标与协议

- **状态**：review
- **信息截止**：2026-11-17
- **核心判断**：世界模型评测的真正对象不是“生成的视频”，而是“动作条件下的状态演化是否可信、可用”。

## 1. 为什么评测难

| 难点 | 具体表现 | 现有缓解 |
| --- | --- | --- |
| 无真值状态 | 真实视频只有像素，没有位姿/速度/接触力 | 用仿真做 oracle（WMEval）；用最小对构造反事实 |
| 指标可被“抄近路” | 复制上一帧即可获得低预测误差 | 配对持续性控制（Prediction or Persistence） |
| 分布内 vs 分布外 | 训练分布内画质完美，边界条件崩溃 | 最小对/密集扫描（FlipTest）、成对实验（SciWorldBench） |
| 长时程 | 10 秒好看，2 分钟后漂移 | 重访、回滚、身份保持测试 |
| 评测工具漂移 | 换配置/预处理就换结论 | 回归测试（TetraState） |
| 下游效用不明 | 预测指标好但策略不提升 | 闭环任务成功率、样本效率 |

一句话：**单一分数不足以定义世界模型质量**。必须同时报告能力剖面与评测稳定性。

## 2. 评测的两个层次

### L1 能力评测（model-centric）

回答“这个模型会什么”：

- 感知保真；
- 物理合理性；
- 状态持久；
- 动作可控；
- 反事实正确；
- 长时程稳定；
- 效率（延迟/吞吐/显存）。

### L2 系统效用（system-centric）

回答“用它能做成什么”：

- 在模型中规划后的真实任务成功率；
- 用合成数据训练策略的样本效率；
- sim-to-real 相关性；
- 人类创作者/用户的任务完成时间与质量；
- 单位内容成本。

本项目两者都要，但**L2 优先**：一个能力剖面平庸但能稳定提升下游任务的模型，比刷榜模型更有价值。

## 3. 现有基准地图

| 基准 | 时间 | 评测对象 | 方法 | 局限 |
| --- | --- | --- | --- | --- |
| **WorldModelBench** | 2025-02 | 视频生成模型 | 指令遵循 + 物理合理性，多维评分 | 偏感知，缺状态真值 |
| **WorldArena 2.0** | 2026-10 | 具身世界模型 | 模态、功能、平台三维扩展 | 仿真为主，真实部署少 |
| **WMEval** | 2026-10 | 交互式世界模型 | Unity 物理仿真作真值，状态级验证 | Unity 域覆盖有限 |
| **FlipTest** | 2026-11 | 视频世界模型 | 1,680 帧、10 仿真 + 15 真实任务；最小对 + 匹配控制 + 密集扫描 | 聚焦状态翻转，不测长时程 |
| **SciWorldBench** | 2026-11 | 视频世界模型 | 成对科学实验，只改一个条件 | 科学域窄 |
| **Prediction or Persistence** | 2026-11 | 机器人世界模型 | 27,000 次未来检索 + 配对持续性控制 | 检索任务，非闭环 |
| **ARC** | 2026-11 | 潜空间世界模型 | 离散 Fréchet 距离 + 仿射规范 + 干预子空间 | 目前主要在低维动力学验证 |
| **TetraState / One Verdict** | 2026-10 | 评测工具本身 | 4 种配置的回归测试 | 方法学，不是能力榜 |
| **VBench-2.0** | 2025-03 | 视频生成 | 内在忠实度（物理、常识、可控） | 生成导向 |
| **Physics-IQ** | 2025-01 | 视频模型物理理解 | 物理事件预测/解释 | 偏感知与问答 |

### 3.1 FlipTest 的关键数字

- 1,680 个初始帧；10 个仿真任务 + 15 个真实任务；
- 11 个视频世界模型全部未通过；
- 最佳模型在真实+仿真上的配对准确率平均 **18.3%**（二选一，随机为 50%，说明模型系统性偏向“不翻转”）。

这组数字说明：**当前视频世界模型主要在学习“视觉上合理的续写”，而不是“跟踪世界状态”**。

### 3.2 Prediction or Persistence 的关键方法

把未来预测分数拆成三部分：

1. 编码器质量；
2. 近期未来与近期过去的相似性（persistence）；
3. 预测器本身的贡献。

做法：每个模型配一个“预测器从不调用”的持续性对照，用配对差值隔离预测能力。结论：很多模型的“预测优势”来自第 2 项，而非真正的动力学建模。

## 4. 建议的指标集

### 4.1 物理与状态

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| **物理违规率 PVR** | 每 100 帧中穿透、悬浮、非守恒、错误接触的比例 | 越低越好 |
| **状态翻转准确率 FSA** | 最小对上预测是否随真实状态翻转 | 越高越好（随机 50%） |
| **身份保持率 IDR** | 遮挡/重访后正确 Re-ID 的比例 | 越高越好 |
| **场景重写率 SRR** | 重访时未观测区域被不合理重写的比例 | 越低越好 |
| **动力学忠实度 DCD** | 潜空间轨迹与真值轨迹的 Fréchet/DTW 距离 | 越低越好 |

### 4.2 动作与反事实

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| **动作敏感度 AS** | 不同动作导致结果分布的差异（KL/效应量） | 高于阈值 |
| **反事实正确率 CFR** | 同一初始状态、不同动作，预测方向正确的比例 | 越高越好 |
| **干预响应 IR** | 对指定物体/属性的干预是否只影响相关部分 | 越高越好 |

### 4.3 长时程与效率

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| **N 步漂移** | 与真值在第 N 步的感知/状态距离 | 随 N 增长缓慢 |
| **记忆衰减半衰期** | 关键信息可被正确检索的最长步数 | 越长越好 |
| **延迟/吞吐** | 端到端 ms、fps | 满足场景预算 |
| **单位分钟成本** | 生成 1 分钟内容的算力/金钱成本 | 越低越好 |

### 4.4 下游效用

| 指标 | 定义 |
| --- | --- |
| **规划成功率** | 在模型中规划后到真实环境的成功率 |
| **样本效率** | 达到目标成功率所需真实交互步数 |
| **sim-to-real 相关性** | 仿真评测排名与真机排名的 Spearman 相关 |
| **人类偏好/任务时间** | 创作者完成指定任务的时间与质量评分 |

## 5. 评测协议草案（与设计方案联动）

### 5.1 测试集构成

1. **合成物理**：已知状态真值的刚体/关节/形变场景（Unity/MuJoCo/Isaac）。
2. **真实视频**：带多视角/深度的短片段，用于重建与重访测试。
3. **反事实最小对**：只改一个初始条件（位置、速度、质量、遮挡），真实未来不同。
4. **长时程回访**：探索 N 步后回到起点，检查状态是否保持。
5. **动作干预**：同一状态施加不同动作，检查结果差异。
6. **领域任务**：叙事场景的剧本一致性、角色身份、镜头连续性。

### 5.2 运行协议

```text
固定初始状态
  → 采样动作序列（脚本化 + 随机 + 对抗）
  → 模型 rollout（记录状态/观测/不确定性）
  → 与 oracle/真实视频对齐
  → 计算分层指标
  → 重复 N 次，报告均值、方差、置信区间
```

必须报告：

- 每个指标的均值与 95% CI；
- 不同随机种子/配置下的方差；
- 失败案例的类型分布，而不只是平均分；
- 与基线的配对比较（不是只报绝对值）。

### 5.3 验收门（示例）

| 阶段 | 指标 | 门槛 |
| --- | --- | --- |
| 原型 | FSA | > 70%（随机 50%） |
| 原型 | PVR | < 5/100 帧 |
| 可用 | IDR（10 次重访） | > 85% |
| 可用 | 动作敏感度 | 显著高于无条件基线（p<0.05） |
| 上线 | 下游任务成功率 | 不低于真实数据训练的 90% |
| 上线 | 延迟 | 满足场景预算（如 15 fps） |

具体阈值需在基线与数据确定后校准；不要先写死再倒推。

## 6. 常见陷阱

1. **只看 FVD/FID**：奖励画质，不奖励状态。
2. **只测短片段**：10 秒内的模型都很好。
3. **不设持续性对照**：把“复制过去”误认为“预测未来”。
4. **不测反事实**：模型可能只是条件平均。
5. **用同一分布调参又评测**：需要 held-out 场景/物体/任务。
6. **忽略评测方差**：单次运行结论不可靠；至少 3 seeds，报告 CI。
7. **把仿真当真理**：仿真器也有偏差；需要真实视频/真机校准。
8. **不记录失败模式**：平均分掩盖系统性缺陷。

## 7. 评测 harness 建议

```text
datasets/        # 场景、初始状态、动作脚本、真值
runners/         # 统一模型接口: reset(), step(action), observe()
oracles/         # 仿真器、真实视频、人工标注
metrics/         # 分层指标实现
reports/         # 自动生成 Markdown/JSON 报告
```

统一接口是关键：不同模型（视频、JEPA、WAM、3D）都实现同一 `step/observe` 协议，才能公平比较。
