## 1. Genie 3（Google DeepMind，2025-08）`C`

**一句话**：把“可交互世界”做成实时视频生成，用户用动作/文本提示探索，模型维持数分钟的场景一致性。

**架构**：据官方博客，基于视频生成骨干的实时自回归世界模型；支持文本/图像提示生成世界、可提示世界事件；720p、24 fps；无需显式 3D 表征。

**强在哪**：

- 实时交互与视觉质量的平衡；
- 可提示事件（promptable world events）让世界可被“导演”；
- 证明世界模型可以作为产品形态存在。

**会怎么坏**：

- 官方承认动作空间有限、文本渲染、多智能体交互、真实地理位置与物理仍有局限；
- 无显式状态，长时程一致性有限（数分钟）；
- 闭源、仅研究访问。

**对我们的启示**：交互式世界模型的用户体验基准；但其“隐式状态 + 视频输出”正是我们要补的短板。

> 本次环境无法访问 DeepMind 原页，规格标为 `C`；见 [待核实清单](06-verification-backlog.md)。

## 2. Cosmos 3（NVIDIA，2026-06）`B`

**一句话**：用一个 omnimodal mixture-of-transformers 同时处理语言、图像、视频、音频与动作，试图把 VLM、视频生成器、世界模拟器、WAM 收进同一骨干。

**架构**：

- 统一模态序列 + mixture-of-transformers；
- 灵活输入输出配置（任意模态 → 任意模态）；
- 后训练覆盖理解、生成、策略。

**关键结果**：官方称在多样理解/生成任务上达到 SOTA；后训练模型被 Artificial Analysis 评为最佳开源文生图/图生视频，被 RoboArena 评为最佳策略模型。

**生态**：

- Cosmos-Predict2.5（2025-10）：流匹配统一 Text/Image/Video2World，200M 视频片段，2B/14B，RL 后训练。
- Interactive World Simulation with Cosmos（2026-11）：实时交互框架，支持动作后果预测与外部物理引擎状态驱动。
- OmniDreams（2026-11）：2.1 万小时驾驶数据，闭环 AV 仿真。
- Cosmos-H-Dreams（2026-08）：手术机器人实时生成物理仿真。

**会怎么坏**：统一骨干的模态冲突、动作数据覆盖、闭环稳定性仍是开放问题；官方 SOTA 声明需独立复现。

**对我们的启示**：最强的开放“底座候选”。我们应把它当 renderer/backbone，而不是重造。

## 3. Atlas / Frameboy（World Labs，2026-09 / 2026-11）`A`

**一句话**：把每张图像锚定在 3D 空间位置形成 spatial context，用多模态自回归扩散 Transformer 统一生成、重建与时空模拟。

**架构**：

- 多模态自回归扩散 Transformer；
- 原生输入：文本、图像、相机位姿、深度；视频 = 图像序列；
- 输出：图像/视频、点云、3DGS；
- 类似 LLM 的 KV cache / 推理优化。

**能力**：

- 相机精确控制的生成，1440p、最长 1 分钟；
- 稀疏视图 3D 重建，官方称优于专用 SOTA；
- 从少量手机视频做 real-to-sim，服务机器人导航/操作；
- Frameboy：云端流式 **15 fps** 实时探索。

**关键判断**：官方明确说 Atlas 不是“更大的 RTFM”，而是从单图/文本从零生成场景；实时性把“生成”变成“探索”，改变创作流程。

**会怎么坏**：1 分钟视频仍有限；动态/多智能体弱；依赖相机位姿；实时需要强 GPU，成本高。

**对我们的启示**：spatial context 是持久状态的一种实现；但它是“空间状态”，不是“对象/因果/叙事状态”。这正是我们的差异化空间。

## 4. Marble / RTFM（World Labs，2025-11 / 2025-10）`A`

**一句话**：Marble 从多模态输入生成可探索、可编辑的持久 3D 世界，输出 3DGS + 碰撞网格；RTFM 是其前代实时帧模型。

**能力**：持久 3D、可导航、可编辑、可导出；碰撞网格让物理引擎可用。

**会怎么坏**：静态场景强、动态弱；生成几何可能不自洽；存储/流式成本。

**对我们的启示**：证明“渲染 + 碰撞/物理”可以共存在一个管线；叙事场景可以复用这套表示做“空间记忆”。

## 5. V-JEPA 2（Meta FAIR，2025-06）`A`

**一句话**：100 万小时以上视频做无动作自监督预训练，再用少量机器人轨迹做动作条件后训练，潜空间预测直接支撑零样本抓取与规划。

**架构**：ViT 编码器 + 动作条件预测器；V-JEPA 2-AC 用机器人轨迹后训练；规划时在潜空间做 MPC/优化。

**关键结果**：Something-Something v2 77.3 top-1；Epic-Kitchens-100 动作预期 39.7 recall@5；零样本机器人操作。

**会怎么坏**：短时程；细粒度物理弱；动作数据仍少；表征忠实度难验证。

**对我们的启示**：如果走“潜空间 + 控制”，V-JEPA 是最成熟的开放起点；但需要补显式状态与验证。

## 6. Dreamer 4（2025-09）`A`

**一句话**：用高效 Transformer 世界模型 + shortcut forcing，在单 GPU 上实时想象，仅凭离线数据在 Minecraft 学会挖钻石。

**架构**：可扩展 Transformer 世界模型；shortcut forcing 实现少步/实时生成；在想象中做 RL。

**关键结果**：Minecraft 对象交互与游戏机制预测大幅超前作；首个仅用离线数据获得钻石的智能体（论文声明）。

**会怎么坏**：领域特定；奖励/任务设计；视觉复杂度上限；长期泛化。

**对我们的启示**：证明“小算力 + 好世界模型 + 想象训练”可行；shortcut forcing 可用于我们的快速 rollout。

## 7. GAIA-2（Wayve，2025-03）`A`

**一句话**：以自车动力学、智能体配置、环境与道路语义为结构化条件，生成多相机时空一致的驾驶视频。

**架构**：潜扩散 + 多相机条件；支持新场景生成与动态智能体插入；覆盖英/美/德。

**会怎么坏**：驾驶域专用；长尾安全场景的物理正确性仍需验证；闭环一致性。

**对我们的启示**：结构化条件是可控性的关键；多相机一致性可以借鉴到多角色/多镜头叙事。

## 8. OmniDreams + Interactive Cosmos（NVIDIA，2026-11）`B`

**一句话**：把 Cosmos 变成实时、动作条件、可闭环的模拟器；既生成动作后果，也能从外部物理引擎状态生成观测。

**关键数字**：OmniDreams 用 2.1 万小时驾驶场景做中级/后训练；实时自回归动作条件视频。

**会怎么坏**：闭环误差累积；生成观测与物理状态漂移；实时算力。

**对我们的启示**：“外部状态 + 神经观测”的混合架构是长时程稳定的现实解；与我们的 PWM 设计一致。

## 9. GE-Act 2.0 / GE-Sim 2.0（AgiBot 智元，2026）`B`

**一句话**：GE-Act 2.0 从零预训练 WAM（CoAE + 单步视觉规划器 + 逆动力学）；GE-Sim 2.0 用数千小时真机数据重训闭环视频模拟器，并加入状态专家与世界裁判。

**架构要点**：

- CoAE：控制导向自编码器，在激进压缩下保留动作/指令相关信息；
- SVP：单步生成完整未来状态；
- IDM：从未来状态反推动作；
- GE-Sim：状态专家从视频潜变量解码本体状态，世界裁判按任务指令评分。

**会怎么坏**：真机数据覆盖；闭环长时程；评测标准。

**对我们的启示**：中国团队在“世界模型 + 策略 + 闭环评测”上已形成完整栈；状态专家/世界裁判是我们验证层的直接参照。

## 10. InternW0（上海 AI Lab，2026-09）`B`

**一句话**：异步多频物理世界模型：重型视频专家做长时程预测，轻量动作专家高频输出，面向部分可观测与外部扰动。

**架构**：非对称 video-action 架构 + flow matching；共享表征但不同时间尺度。

**会怎么坏**：多频同步；动作数据；真实部署。

**对我们的启示**：多时间尺度是我们设计中的关键机制；InternW0 证明了“慢思考 + 快行动”的工程可行性。

## 11. GreenWAM（2026-10）`B`

**一句话**：用统一解剖动作空间覆盖 20 种机器人，同一模型兼顾世界模型与策略，在 WorldArena 1.0 上领先。

**架构**：共享动作空间 + 视觉/动作条件/世界-动作三模式联合训练 + 从生成器拆出动作专家。

**会怎么坏**：跨本体语义对齐；数据不均衡；评测偏仿真。

**对我们的启示**：跨本体动作空间是规模化关键；如果未来扩展到机器人，这是最值得复用的接口设计。

## 12. WorldPlay / DreamX-World / GameWM（2025–2026）`B`

**一句话**：三条解决“实时 + 长期一致性 + 可控”的不同路径。

| 系统 | 核心机制 | 解决什么 |
| --- | --- | --- |
| **WorldPlay** | 双动作表示 + 重构式上下文记忆 + Context Forcing | 实时与长期几何一致性的权衡 |
| **DreamX-World 1.0** | E-PRoPE 相机编码 + 少步自回归 | 相机导航、重访、可提示事件 |
| **GameWM** | 引擎保留精确状态，视频模型生成内容 | 规则/状态精确性 vs 生成多样性 |

**对我们的启示**：三者可以组合成“引擎/状态层 + 视频渲染层 + 记忆层”的完整架构。

## 13. Physical Registry（2026-10）`B`

**一句话**：在视频 DiT 内加入时间上接地的 registry slots，给预测动力学一个独立、可读的内部状态，而不是让外观与动力学混在视频 token 里。

**为什么重要**：直接回应“预测应该住在生成器的哪里”这个架构问题；与我们的“状态层”设计高度同构。

**会怎么坏**：状态槽的语义监督；与像素生成的耦合；规模化验证。

**对我们的启示**：这是最接近我们“显式状态 + 神经渲染”思路的学术工作，应作为核心 related work 与基线。

## 14. SIMA 2（Google DeepMind，2025-12）`A`

**会怎么坏**：虚拟世界与真实机器人差距；动作接口；长期自主。

**对我们的启示**：世界模型需要“智能体 counterpart”；叙事场景中的“角色智能体”可以借鉴 SIMA 的目标分解与对话交互。

## 横向观察

1. **开放程度**：NVIDIA Cosmos 最开放；Meta V-JEPA 开放；World Labs 提供 API；Google/OpenAI 闭源。
2. **状态表示**：越往“可验证/可编辑”走，越倾向显式状态（Atlas spatial context、Physical Registry、GameWM engine）。
3. **实时性**：2026 年从“能生成”变成“能交互”；15 fps 是当前产品级参考线。
4. **机器人**：WAM 已成主流叙事；闭环仿真与状态专家/裁判是标配。
5. **叙事/影视**：几乎空白。现有系统优化空间一致性，不优化角色身份、世界观、剧情因果——这是本项目的切入口。
