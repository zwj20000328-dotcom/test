# 世界模型技术路线对比

- **状态**：review
- **信息截止**：2026-11-17
- **用途**：回答“每条路线怎么工作、什么时候选它、它会怎么坏”
- **配套**：[全景报告](01-landscape.md) · [系统卡片](03-representative-systems.md)

## 0. 一个统一的形式化

任何世界模型都可以写成三元组：

\[
\underbrace{E_\phi}_{\text{表征}} \quad+\quad \underbrace{f_\theta}_{\text{动力学}} \quad+\quad \underbrace{R_\psi}_{\text{读出/解码}}
\]

- \(E_\phi: o_{\le t} \mapsto z_t\)：把观测压成状态（显式或隐式）。
- \(f_\theta: (z_t, a_t) \mapsto z_{t+1}\)：动作条件动力学。
- \(R_\psi: z_t \mapsto \hat{o}_t\) 或 \(\hat{a}_t\)：解码为像素、3D、动作或语义。

不同路线的差异，本质上是**状态放在哪个空间**：

| 状态空间 | 典型维度 | 优点 | 缺点 | 路线 |
| --- | --- | --- | --- | --- |
| 像素/视频 token | 高（10⁴–10⁶） | 信息全、可用互联网视频 | 状态纠缠、难验证、贵 | 视频生成式 |
| 潜嵌入 | 中（10²–10⁴） | 高效、语义强、适合规划 | 物理细节弱、需防坍塌 | JEPA / MBRL |
| 显式 3D | 中高（点/高斯/网格） | 持久、可导航、可编辑 | 动态弱、数据稀缺 | 3D 场景 |
| 结构化状态 | 低–中（物体/关系/物理量） | 可读、可验证、可回滚 | 感知抽取难、覆盖有限 | 混合/物理 |
| 联合状态-动作 | 中 | 直接服务决策 | 动作数据贵、跨本体难 | WAM |

一个重要的工程判断：**状态空间的选择比模型规模更决定系统的失效模式**。像素空间的世界模型会漂移；潜空间的世界模型会“语义正确但物理模糊”；结构化世界模型会受感知瓶颈拖累。

## 1. 路线 A：视频生成式（Renderer-first）

### 1.1 形式

学习观测序列的生成分布：

\[
p_\theta(o_{t+1:t+k}\mid o_{\le t}, c_t)
\]

\(c_t\) 可以是文本、相机位姿、动作、场景布局或参考图。训练目标通常是扩散/流匹配的去噪损失，或自回归 token 的交叉熵。

### 1.2 三种骨干

| 骨干 | 代表 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **潜扩散 + DiT** | Sora、Cosmos、GAIA-2、OmniDreams | 画质高、可控、生态成熟 | 推理慢、长视频贵 |
| **自回归视频 token** | Genie、Cosmos AR、Atlas | 流式、可变长、易接 KV cache | 误差累积、tokenizer 损失 |
| **混合 AR + diffusion** | Atlas、Causal-rCM | 兼顾流式与画质 | 系统复杂、蒸馏难 |

### 1.3 动作如何进入

1. **显式动作向量**：机器人关节/末端位姿、自车速度/转角。GAIA-2 用结构化条件；OmniDreams 用动作条件。
2. **潜在动作**：从相邻帧推断一个离散/连续动作码，让无动作视频可训练（Genie）。
3. **相机/视角控制**：Atlas 原生接受相机位姿与深度；DreamX 用 E-PRoPE。
4. **文本/图像条件**：最通用，但控制粒度最粗。

### 1.4 长时一致性技巧

- **KV cache + 滑动窗口**：流式生成的基础，但窗口外信息会丢失。
- **重构式上下文记忆**：WorldPlay 从过去帧重建上下文，并用时间重定帧保留久远但几何重要的帧。
- **空间上下文**：Atlas 把每张图锚定在 3D 位置，生成时保持 3D 一致，而不是仅靠帧序列。
- **有效时间记忆**：Old Is Not False 区分“时间戳最新”与“状态最新”，处理撤销/回访。
- **分层生成**：先生成关键帧/布局，再生成细节；降低长时漂移。

### 1.5 实时化

| 手段 | 代表 | 代价 |
| --- | --- | --- |
| 少步蒸馏 | Causal-rCM、Context Forcing、shortcut forcing | 画质/多样性损失 |
| 缓存复用 | CtrlCache、CAST、QuantWM | 控制变化时缓存失效 |
| 模型缩小/稀疏化 | minWM、Nano 档 Cosmos | 容量下降 |
| 异步系统 | 云端流式（Frameboy 15 fps） | 网络延迟、成本 |

### 1.6 什么时候选它

**适合**：视觉保真优先、需要开放域泛化、有大量视频、可接受离线或准实时、下游是人类消费者。

**不适合**：需要精确物理、需要长期状态回滚、需要可解释状态、边缘设备、严格实时闭环。

### 1.7 典型失效

- **状态漂移**：物体位置/身份随生成步数漂移。
- **反事实失败**：小变化不改变预测（FlipTest）。
- **动作不敏感**：动作条件被文本/历史主导。
- **记忆重写**：镜头回来后场景被“重新想象”。
- **评估幻觉**：FVD 好但物理错。

## 2. 路线 B：潜空间预测（JEPA 家族）

### 2.1 形式

不重建 \(o\)，而在表征空间预测：

\[
\mathcal{L} = \big\lVert P_\theta(E_\phi(o_{\le t}), a_t) - \operatorname{sg}(E_{\bar\phi}(o_{t+1})) \big\rVert
\]

其中 \(\operatorname{sg}\) 是 stop-gradient，\(\bar\phi\) 是目标编码器（EMA 或冻结）。规划时在潜空间优化动作序列：

\[
a^*_{t:t+H} = \arg\min_{a} \sum_{h=1}^{H} \big\lVert P^h(E(o_t), a_{t:t+h}) - E(o_{\text{goal}}) \big\rVert
\]

### 2.2 防坍塌

| 机制 | 代表 | 问题 |
| --- | --- | --- |
| 目标网络 + stop-gradient | I-JEPA/V-JEPA | 需要调 EMA/温度 |
| 方差/协方差正则 | VICReg 类 | 超参敏感 |
| 分布匹配 | DINO 类 | 依赖大量数据 |
| 有向距离交叉熵 | Sense（2026） | 新，需更多验证 |

Sense 的洞察值得注意：防坍塌机制能让表征不塌，但**不保证距离有语义**；一个不能区分“可逆”与“不可逆”转移的潜空间，无法支撑反事实规划。

### 2.3 动作条件

- **V-JEPA 2-AC**：在无动作预训练后，用少量机器人轨迹训练动作条件预测器。
- **DINO-WM**：冻结 DINOv2，学习动作条件动力学，测试时零样本规划。
- **JEPA4R**：把状态扩展到 4D 点云，直接服务操作。
- **WA-JEPA**：动作提案 + 预测反馈，避免候选搜索。

### 2.4 什么时候选它

**适合**：机器人控制、样本效率敏感、需要语义泛化、算力有限、可接受短时程。

**不适合**：需要照片级渲染、需要精确接触/形变、需要人类直接观看、长时程复杂场景。

### 2.5 典型失效

- **表征不忠实**：能解码但动力学错误（ARC 的动机）。
- **短时程**：几步后语义漂移。
- **动作数据瓶颈**：没有动作标签就无法真正条件化。
- **静态度量陷阱**：文本对齐的表征丢掉动力学（V-JEPA-LM）。

## 3. 路线 C：模型基强化学习（MBRL）

### 3.1 形式

学习紧凑状态空间模型 \(p(z_{t+1}\mid z_t,a_t)\)、奖励/终止预测，然后在模型中展开想象轨迹优化策略：

\[
\max_\pi \mathbb{E}_{z_0\sim \mathcal{D},\, a\sim\pi}\left[\sum_{t=0}^{H}\gamma^t \hat{r}(z_t,a_t)\right]
\]

### 3.2 代表

- **DreamerV3**：RSSM 的 categorical latent + 对称 log 变换 + 两热编码，单套超参跨 150+ 任务。
- **Dreamer 4**：Transformer 世界模型 + shortcut forcing，单 GPU 实时；离线 Minecraft 数据学会挖钻石。
- **TD-MPC2**：无解码器隐式模型 + 局部轨迹优化；317M 参数多任务。

### 3.3 什么时候选它

**适合**：有明确奖励/任务、可交互仿真、需要样本效率、状态维度不高。

**不适合**：开放域、无奖励、需要人类可读的世界、视觉极其复杂。

### 3.4 典型失效

- 奖励黑客：在模型漏洞里刷分。
- 模型偏差被策略利用：想象中成功，真实失败。
- 领域过窄：换任务需重训。

## 4. 路线 D：3D / 场景中心

### 4.1 形式

把世界表示为显式结构：

- 3D Gaussian Splatting（3DGS）：\( \{(\mu_i,\Sigma_i,\alpha_i,c_i)\} \)，可微渲染。
- 点云/深度：几何直接可计算。
- 网格/碰撞体：物理引擎可用。
- 神经辐射场（NeRF）：隐式但可查询。

生成式 3D 世界模型的典型管线（以 HY-World 2.0 为例）：

```text
文本/图像/视频
   → 全景/多视图生成
   → 相机轨迹规划
   → 世界扩展（外推未观测区域）
   → 3DGS 组合 / 网格导出
```

### 4.2 2026 年的关键进展

- **Atlas**：把生成与重建统一，原生输出点云/3DGS，稀疏视图重建优于专用模型。
- **Marble**：同时输出 Gaussian splats 与碰撞网格，打通渲染与物理。
- **HY-World 2.0**：多模态输入 → 3DGS，四阶段可组合。
- **RTFM/Frameboy**：用持久 3D 上下文缓存实现实时新视角生成。
- **AEON**：尝试统一视频与 3D 世界模型。

### 4.3 什么时候选它

**适合**：需要持久空间、可导航、可编辑、需要物理引擎/机器人管线、静态或半静态场景。

**不适合**：高度动态、多智能体交互、需要照片级人物表演、存储/实时预算极紧。

### 4.4 典型失效

- 生成几何自交/尺度错误 → 物理无意义。
- 未观测区域“想象”与真实不符。
- 动态物体被烘进静态场景。
- 3DGS 存储与流式传输成本。

## 5. 路线 E：世界-动作模型（WAM）

### 5.1 为什么出现

VLA（Vision-Language-Action）直接从观测映射动作，没有显式未来预测；世界模型预测未来但不输出动作。WAM 把两者合并：

\[
p_\theta(o_{t+1:t+k}, a_{t:t+k}\mid o_{\le t}, \ell)
\]

好处：

- 策略可以利用“如果我这样做，世界会怎样”的预测；
- 无动作视频可以提供动力学先验；
- 预测与控制共享表征，减少接口损失。

### 5.2 三种架构

| 架构 | 代表 | 描述 | 风险 |
| --- | --- | --- | --- |
| **Video-first** | Genie Envisioner、GE-Sim | 先训视频世界模型，再接动作头/逆动力学 | 视频预训练目标与动作需求错位 |
| **Joint** | Cosmos 3、GE-Act 2.0、GreenWAM | 视频与动作联合生成/训练 | 训练成本高、模态冲突 |
| **Structured** | Magic-W0、InternW0 | 显式状态/转移/动作分层 | 结构设计依赖领域知识 |

### 5.3 动作空间问题

- **跨本体**：不同机器人关节数/语义不同。GreenWAM 用“统一解剖动作空间”描述 20 种机器人；Cosmos 3 把动作作为 omnimodal 序列的一种。
- **无动作视频**：潜在动作（Genie）、从基础模型抽取（OnlyAct）、光流/轨迹代理（FlowWAM）。
- **动作表征与视觉对齐**：SWAM 发现动作学习可能破坏语言-视频对齐，需要专门的数据/监督设计。

### 5.4 监督效率

ResWAM 的关键洞察：动作块内大部分像素不变，完整未来监督会被静态背景主导。更好的做法是**只监督变化部分**，或使用差分/运动表征。

### 5.5 什么时候选它

**适合**：机器人操作、自动驾驶、需要策略与世界模型共享知识、有仿真/遥操作数据。

**不适合**：纯内容生成、没有动作数据、只需要静态 3D。

### 5.6 典型失效

- 动作条件被视觉先验淹没（模型忽略动作）。
- 闭环误差累积。
- 跨本体迁移失败。
- 仿真评测与真机不相关。

## 6. 路线 F：交互、实时与记忆

### 6.1 延迟预算

以 15 fps 为例，端到端预算约 66 ms，包含：

```text
输入编码 (5-10ms) → 动力学/去噪 (30-50ms) → 解码 (5-10ms) → 网络/显示 (5-15ms)
```

这决定了必须使用少步蒸馏、缓存、模型缩小与异步流水线。

### 6.2 记忆的三种范式

| 范式 | 代表 | 机制 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| **上下文窗口** | 多数视频模型 | KV cache / 滑动窗口 | 简单 | 窗口外遗忘 |
| **重构式记忆** | WorldPlay | 从过去帧重建上下文 | 长期几何一致 | 计算/存储开销 |
| **时间数据库** | Old Is Not False | 记录有效时间与状态版本 | 正确处理撤销/回访 | 需要状态语义 |
| **空间上下文** | Atlas | 图像锚定 3D 位置 | 3D 一致、可重访 | 依赖位姿/深度 |

### 6.3 什么时候选它

**适合**：游戏、内容创作、交互式叙事、机器人遥操作界面、数据采集。

**不适合**：离线批量生成（不需要实时）、算力受限的边缘设备、需要严格物理保证的场景。

## 7. 路线 G：混合、结构化与物理约束

### 7.1 核心模式

```text
        ┌──────────────┐
动作 ──→│ 精确模块      │──→ 状态（规则/物理/几何）
        │ 引擎/物理/符号│
        └──────┬───────┘
               │ 状态
               ▼
        ┌──────────────┐
        │ 学习模块      │──→ 观测（渲染/补全/风格）
        │ 视频/神经渲染 │
        └──────────────┘
```

代表：

- **GameWM**：引擎保留规则、状态、相机、布局；视频模型生成手工昂贵的内容。
- **Interactive Cosmos**：外部物理引擎维护状态，Cosmos 生成观测。
- **Physical Registry**：在视频 DiT 内加入独立状态槽，让动力学有可读的内部状态。
- **R2S2R**：真实任务 → 可交互仿真 → 策略训练/评测 → 真机。
- **Frame First**：物体中心 SE(2) 坐标，降低学习难度与决策遗憾。

### 7.2 什么时候选它

**适合**：需要长时程稳定、物理可验证、可编辑、工程可控；机器人/驾驶/游戏/工业仿真。

**不适合**：开放域、无法手工建模、追求纯粹端到端学习。

### 7.3 典型失效

- 感知到状态的抽取误差累积。
- 混合接口的误差归因困难。
- 手工建模范围限制泛化。
- 系统工程复杂度高。

## 8. 选型矩阵

| 目标 | 首选路线 | 次选 | 关键指标 |
| --- | --- | --- | --- |
| 视觉内容生成 | 视频生成式 | 3D 场景 | 人类偏好、可控性、成本 |
| 机器人操作 | WAM / JEPA | MBRL | 任务成功率、样本效率、sim-to-real |
| 自动驾驶仿真 | 视频生成式 + 闭环 | 3D 场景 | 多相机一致、长尾覆盖、实时 |
| 可探索 3D 世界 | 3D 场景 | 视频 + 重建 | 几何一致、可编辑、持久 |
| 实时游戏/交互 | 混合（引擎 + 视频） | 流式视频 | 延迟、长期一致性、可控 |
| 小算力控制 | MBRL / JEPA | 结构化 | 样本效率、稳定性 |
| 长时程物理推演 | 混合/结构化 | 视频 + 验证 | 状态准确、物理违规率 |
| 叙事/影视一致性 | 结构化状态 + 视频渲染 | 3D 场景 | 身份/世界观一致性、可编辑 |

## 9. 共同失效模式

1. **误差累积**：自回归越长越偏；需要闭环校正、关键帧锚定、记忆。
2. **动作条件塌缩**：模型忽略动作，退化为无条件生成；需要动作敏感度测试与反事实训练。
3. **状态不可读**：无法检查/编辑/回滚；需要显式状态或状态探针。
4. **分布外物理崩溃**：训练分布内完美，边界条件失败；需要最小对/反事实评测。
5. **评测噪声**：指标与下游效用脱节；需要多层指标 + 回归测试。
6. **数据偏差**：互联网视频缺动作、缺物理标注；仿真有 sim-to-real gap；机器人数据覆盖窄。

## 10. 对本项目的建议

- **不要从零训练视频基础模型**。把开源骨干（Cosmos、V-JEPA、Atlas API、开源视频模型）当作 renderer/encoder，把创新集中在状态层与验证层。
- **优先结构化状态 + 潜空间动力学**，而不是纯像素自回归。理由：可验证、可回滚、长时程更稳、算力更可控。
- **把“变化”作为预测目标**：ResWAM、Frame First、LaST0.5 的结论都指向“只学变化的部分”更有效。
- **实时性从第一天设计**：蒸馏、缓存、异步是架构约束，不是后期优化。
- **评测先行**：在扩大模型前先建立 FlipTest/WMEval 风格的闭环验收。

具体方案见 [PWM 设计方案](../02-design/01-proposal.md)。
