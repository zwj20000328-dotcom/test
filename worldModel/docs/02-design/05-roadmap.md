## 1. 总体节奏

```text
2026 Q4        2027 Q1        2027 Q2        2027 Q3        2027 Q4 – 2028 Q1
Phase 0        Phase 1        Phase 2        Phase 3        Phase 4
立项/基线      状态+动力学     叙事原型       长时程+实时     规模化/扩展
4 周           12 周          12 周          12 周          16 周
```

每个阶段结束做 go/no-go；不达标就缩范围或换垂直，不硬推。

## 2. 阶段详情

### Phase 0：立项与基线（2026-11 ~ 2026-12，4 周）

**目标**：把“要不要做、怎么做、用什么衡量”确定下来。

| 交付物 | 负责人 | 验收 |
| --- | --- | --- |
| 调研报告定稿（全景/路线/评测/开放问题） | 研究 lead | 评审通过 |
| 待核实清单 P0 项处理 | 研究 lead | Genie/Sora/FlipTest 数字至少核实 3 项 |
| 评测 harness v0（S1/S2） | ML eng | 能跑 persistence + 一个开源基线 |
| Canon/状态 schema v0 | 架构 + 编剧 | 能表达 3 集现有剧本 |
| 基线复现（V-JEPA 2 / DINO-WM / 开源视频模型） | ML eng | 指标可复现 |
| 数据/版权清单 | 产品/法务 | 资产来源可追溯 |

**决策门 G0**：

- 是否确认叙事/短剧为首个垂直？
- 是否有足够数据与算力启动 Phase 1？
- 评测 harness 是否能区分“预测”与“复制”？

### Phase 1：状态与动力学（2027-01 ~ 2027-03，12 周）

**目标**：证明“显式持久状态 + 潜动力学”在受控场景中优于纯视频基线。

| 工作流 | 交付物 |
| --- | --- |
| 状态服务 | WSG v0（SQLite + JSON schema）、事件日志、checkpoint |
| 动力学 | 冻结 DINOv2/V-JEPA + Transformer 预测器；增量预测 |
| 验证器 | 规则版：实体永久、身份、canon、知识状态 |
| 渲染 | 一个视频后端（图生视频/首尾帧） |
| 评测 | S1/S2 完整跑通；报告 CI 与失败分布 |
| 文档 | 技术报告草稿（状态表示 + 初步结果） |

**决策门 G1**：

- H1 是否成立（10 次重访 IDR +30%）？
- 验证器误报率是否可接受（<15%）？
- 如果没有显著提升，是否改用“视频 + 记忆”方案？

### Phase 2：叙事原型（2027-04 ~ 2027-06，12 周）

**目标**：跑通一个可演示的跨集叙事世界。

| 工作流 | 交付物 |
| --- | --- |
| 事件/镜头动作 | 语义动作 schema、镜头控制接口 |
| 状态抽取 | 从剧本/视频抽取实体/关系/事件，人工校正 |
| 验证器 | canon/知识/因果/风格规则；矛盾定位 |
| 分支 | what-if 基础能力（2–4 分支） |
| 渲染 | 角色身份/场景一致性条件；镜头级控制 |
| 评测 | S3/S5；30+ 片段人类评估 |
| 集成 | 与现有短剧管线的最小闭环 |

**决策门 G2**：

- 跨 10 集 canon 矛盾率 < 5%？
- 人类偏好胜率 > 60%？
- 单分钟成本是否可接受？

### Phase 3：长时程与实时（2027-07 ~ 2027-09，12 周）

**目标**：从“能演示”到“能持续用”。

| 工作流 | 交付物 |
| --- | --- |
| 长时程 | 事件溯源、bitemporal 记忆、retcon 传播 |
| 分支管理 | 剪枝/评分/合并；分支树 UI |
| 实时 | 少步蒸馏、缓存、异步 System-2；5–10 fps |
| 3D 后端 | 3DGS/引擎混合（可选） |
| 评测 | S4/S6/S7；回归测试 |
| 文档 | 第二篇论文/技术报告 |

**决策门 G3**：

- 30 分钟交互是否稳定（hard 矛盾 < 3）？
- 是否达到 5–10 fps？15 fps 的路径是否清晰？
- 是否可产品化（成本/稳定性/合规）？

### Phase 4：规模化与扩展（2027-10 ~ 2028-01，16 周）

**目标**：多集/多季、成本优化、决定是否扩展到其他垂直。

| 工作流 | 交付物 |
| --- | --- |
| 规模 | 多季 canon、更多角色/场景、并发世界 |
| 成本 | 渲染/存储/推理成本优化 |
| 质量 | 叙事质量评估、观众反馈 |
| 扩展评估 | 机器人/游戏/驾驶的可行性与差距 |
| 论文/演示 | 顶会投稿、行业演示 |

**决策门 G4**：

- 是否扩展到机器人/游戏？
- 是否开源评测 harness/部分组件？
- 下一年的资源与目标？

## 3. 工作流与人员

| 工作流 | 角色 | 主要职责 |
| --- | --- | --- |
| 研究 | 研究 lead + 1–2 研究工程师 | 状态表示、动力学、验证、论文 |
| 生成/渲染 | 1 生成模型工程师 | 视频/3D 渲染器、蒸馏、一致性 |
| 平台 | 1 后端/基础设施 | 状态服务、事件总线、部署、可观测 |
| 数据/标注 | 1 数据工程师 + 标注 | 数据管线、canon 抽取、评测集 |
| 产品/叙事 | 1 产品 + 编剧顾问 | 场景定义、canon、人类评估 |
| 全栈/工具 | 1 全栈 | API、编辑器、演示 |

最小团队：5–6 人（研究 2、生成 1、平台 1、数据 1、产品/叙事 1）。可先兼职。

## 5. 关键风险与应对（项目级）

| 风险 | 触发信号 | 应对 |
| --- | --- | --- |
| 技术路线不成立 | H1 不显著、验证器误报高 | 回退到“视频+记忆”；保留评测/数据资产 |
| 渲染成本失控 | 单分钟成本高于传统 | 降分辨率/帧率；缓存；混合后端；限制交互时长 |
| 数据/版权受阻 | 资产无法授权 | 合成数据；公开数据；改写剧本 |
| 团队精力分散 | 同时做机器人/游戏/叙事 | 垂直优先；冻结非核心需求 |
| 基础模型迭代冲击 | 新模型直接支持状态/记忆 | 快速接入；差异化转向验证/叙事 |
| 评测不可信 | 指标与人工评估背离 | 加人类评估；回归测试；失败分析 |
| 合规/滥用 | 肖像/版权投诉 | 同意书、水印、审核、下架机制 |

## 6. KPI

### 技术 KPI

- 重访身份保持 IDR；
- 物理违规率 PVR；
- 反事实正确率 CFR；
- 跨集 canon 矛盾率；
- 交互延迟/fps；
- 单分钟成本。

### 项目 KPI

- 每阶段决策门按时通过；
- 评测 harness 可复现率 100%；
- 文档/资源索引更新及时率；
- 论文/技术报告数量；
- 与现有管线的集成度。

### 业务 KPI（叙事垂直）

- 编剧任务时间降低；
- 可用镜头率；
- 观众偏好；
- 单集制作成本。

## 9. 停止/转向标准

出现以下情况，应认真考虑停止或转向：

1. 两个阶段后 H1/H4 仍不成立；
2. 渲染成本无法降到业务可接受；
3. 评测无法区分模型优劣（指标失效）；
4. 数据/版权成为硬约束；
5. 基础模型厂商直接提供同等能力且成本更低。

转向选项：

- 从“世界模型系统”转为“评测/验证工具”；
- 从叙事转为游戏/教育/工业仿真；
- 从自研转为集成商（用 Atlas/Cosmos API）。
