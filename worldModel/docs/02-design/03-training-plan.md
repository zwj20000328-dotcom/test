- **状态**：draft

- **日期**：2026-11-17
- **关联**：[架构](02-architecture.md) · [方案](01-proposal.md)

## 1. 训练哲学

1. **复用 > 自研**：视觉编码器、视频渲染器、部分动力学骨干优先用开源/商用模型；自研集中在状态抽取、动力学适配、验证器。
2. **先结构后规模**：先用小模型 + 显式状态跑通闭环，再扩规模；避免“大模型掩盖结构问题”。
3. **变化优先**：预测增量/变化，而不是完整观测；减少静态背景主导。
4. **验证驱动**：每个训练阶段都配可证伪评测；不达标不进入下一阶段。
5. **数据分层**：互联网视频学先验，仿真学动作/物理，领域资产学 canon/风格，交互日志学偏好。

## 2. 模型选型

| 模块 | 首选 | 备选 | 理由 |
| --- | --- | --- | --- |
| 视觉编码器 | DINOv2 / V-JEPA 2（冻结） | CLIP、SigLIP | 语义强、可冻结、社区成熟 |
| 实体槽提取 | SlotAttention 变体 / 检测+跟踪 | 分割模型 + Re-ID | 需要稳定 ID |
| 动力学 | 小型 Transformer（6–12 层） | Mamba、DiT | 动作条件、多尺度 |
| 动作编码 | MLP + 文本/图编码 | 潜动作适配器 | 三类动作统一 |
| 不确定性 | 异方差高斯/分位数头 | 深度集成 | 需要校准 |
| 渲染器 | 开源图生视频/首尾帧模型 | Cosmos、Atlas API | 先跑通，不锁定 |
| 验证器 | 规则引擎 + 轻量分类器 | LLM 辅助 | 可解释、可维护 |
| 3D 后端 | 3DGS（Phase 3） | NeRF、点云 | 持久空间 |

> 不在 Phase 1 自研视频生成骨干；渲染器通过统一接口接入。

## 3. 数据计划

### 3.1 来源

| 来源 | 规模（目标） | 用途 | 获取方式 |
| --- | --- | --- | --- |
| 互联网视频 | 现有开源数据集（数千小时起） | 自监督预训练 | 公开数据集/授权 |
| 仿真/游戏 | 可无限生成 | 动作、物理、反事实 | Unity/MuJoCo/Isaac/自建 |
| 短剧资产 | 现有项目积累 | canon、角色、镜头风格 | 内部授权 |
| 人类交互 | 持续采集 | 编辑偏好、分支选择 | 产品内采集（需同意） |
| 标注 | 1–5 万条事件/矛盾 | 监督验证器 | 内部标注 + 合成 |

### 3.2 数据管线

```text
采集 → 清洗/去重 → 版权/同意检查 → 标注 → 特征提取 → 分片存储
   → 训练集/验证集/测试集（按场景/角色/剧集划分，避免泄漏）
```

**划分原则**：测试集必须包含未见角色组合、未见场景、未见因果链；不能只随机划分帧。

### 3.3 标注 schema

事件标注：

```json
{
  "clip_id": "ep01_sc03",
  "t": [12.4, 18.2],
  "entities": ["char_lin", "char_zhou"],
  "events": [

  ],
  "canon_refs": ["f001", "r001"],
  "camera": { "shot": "medium", "movement": "push_in" }
}
```

矛盾标注：

```json
{
  "world_id": "drama_s1",
  "type": "knowledge_violation",
  "entities": ["char_gu"],
  "evidence": ["evt_00123"],
  "severity": "hard",
  "repair": "add_witness"

```

## 4. 训练阶段

### Stage A：自监督预训练

| 项 | 内容 |
| --- | --- |
| 目标 | 视觉编码器 + 实体槽 + 潜动力学 |
| 数据 | L1 互联网视频 + L2 仿真 |
| 损失 | 潜空间预测（JEPA 式）+ 重建（采样）+ 槽一致性 |
| 冻结 | 编码器优先冻结；槽/动力学可训练 |
| 算力 | 4–8×H100 × 2–3 周 |
| 验收 | 短时程预测优于 persistence baseline；槽稳定性 > 阈值 |

### Stage B：动作条件

| 项 | 内容 |
| --- | --- |
| 目标 | 物理/语义动作条件化 |
| 数据 | L2 仿真 + L3 领域 + 少量 L5 标注 |
| 损失 | 动作条件预测 + 逆动力学 + 动作敏感度对比 |
| 技巧 | 动作 dropout 防塌缩；潜动作弱监督 |
| 算力 | 4–8×H100 × 2 周 |
| 验收 | 动作敏感度显著 > 无条件；反事实方向正确率 > 60% |

### Stage C：结构化状态

| 项 | 内容 |
| --- | --- |
| 目标 | 从观测/文本抽取实体、关系、事件、canon |
| 数据 | L3 领域 + L5 标注 |
| 损失 | 实体/关系/事件分类 + 图一致性 + 身份对比 |
| 技巧 | 规则后处理；人工校正回流 |
| 算力 | 2–4×H100 × 2 周 |
| 验收 | 实体 F1 > 0.85；关系 F1 > 0.75；ID 稳定 |

### Stage D：验证与修复

| 项 | 内容 |
| --- | --- |
| 目标 | 不变量检查、矛盾定位、修复排序 |
| 数据 | L2 合成矛盾 + L5 人工标注 |
| 损失 | 矛盾分类 + 定位 + 修复策略排序 |
| 技巧 | 规则引擎冷启动；学习型逐步替换 |
| 算力 | 2–4×H100 × 2 周 |
| 验收 | 矛盾召回 > 0.8；误报 < 15%；修复后复检通过率 > 0.7 |

### Stage E：想象中 RL / 规划

| 项 | 内容 |
| --- | --- |
| 目标 | 在模型中优化动作/镜头/分支 |
| 数据 | L2 + 模型 rollout |
| 奖励 | 任务成功 + canon 一致 + 人类偏好（可选） |
| 技巧 | 短 horizon、模型集成、保守惩罚 |
| 算力 | 4–8×H100 × 2–4 周 |
| 验收 | 真实环境/人类评估优于随机/规则基线 |

### Stage F：实时蒸馏

| 项 | 内容 |
| --- | --- |
| 目标 | 少步渲染/动力学，5–15 fps |
| 数据 | 教师模型 rollout |
| 损失 | 蒸馏 + 对抗/感知（可选） |
| 技巧 | Causal-rCM/Context Forcing 思路；缓存 |
| 算力 | 8–16×H100 × 3–4 周 |
| 验收 | 延迟达标；质量下降 < 10% |

### Stage G：持续学习

| 项 | 内容 |
| --- | --- |
| 目标 | 从交互日志更新状态抽取/验证器/偏好 |
| 数据 | L4 |
| 损失 | 偏好/纠正 + 回归约束 |
| 技巧 | 版本化模型、A/B、回滚 |
| 算力 | 持续小规模 |
| 验收 | 不遗忘旧能力（回归测试通过） |

## 5. 课程设计

| 阶段 | 场景 | 实体数 | 时长 | 动作类型 | 评测 |
| --- | --- | --- | --- | --- | --- |
| C1 | 单房间 | 1–3 | 10 s | 物理 | S1 |
| C2 | 单场景 | 3–8 | 1 min | 物理 + 相机 | S1/S2 |
| C3 | 多场景 | 8–20 | 5 min | 语义 | S2/S3 |
| C4 | 跨集 | 20+ | 30 min | 编辑/分支 | S4/S5 |
| C5 | 多季 | 50+ | 数小时 | 全类型 | S5/S7 |

每个阶段通过后才进入下一阶段；否则回退课程。

## 6. 损失权重建议（起点）

| 损失 | 权重 | 说明 |
| --- | --- | --- |
| \(\mathcal{L}_{latent}\) | 1.0 | 主预测目标 |
| \(\mathcal{L}_{obs}\) | 0.2 | 采样帧重建，避免过度 |
| \(\mathcal{L}_{phys}\) | 0.5 | 物理约束，按场景启用 |
| \(\mathcal{L}_{inv}\) | 0.3 | 逆动力学 |
| \(\mathcal{L}_{cal}\) | 0.1 | 不确定性校准 |
| \(\mathcal{L}_{struct}\) | 0.5 | 身份/图/canon |
| \(\mathcal{L}_{task}\) | 0.3 | 下游任务 |

权重需通过消融确定；不要直接照搬。

## 7. 基线

| 基线 | 用途 |
| --- | --- |
| Persistence（复制上一帧） | 最低门槛；防止“预测”不如复制 |
| 开源视频模型（零样本） | 渲染质量基线 |
| V-JEPA 2 / DINO-WM | 潜空间预测基线 |
| Dreamer 4 / TD-MPC2 | 想象训练基线 |
| Atlas/Marble API | 3D 场景基线 |
| 现有短剧管线 | 领域效用基线 |

## 8. 训练风险

| 风险 | 表现 | 缓解 |
| --- | --- | --- |
| 动作条件塌缩 | 不同动作预测相同 | 动作敏感度损失、dropout、反事实增广 |
| 表征坍塌 | 所有观测映射到同一点 | EMA/stop-grad、方差正则、Sense 类损失 |
| 过拟合领域 | 换场景崩溃 | 域随机化、held-out 场景 |
| 验证器被钻空子 | 策略利用规则漏洞 | 规则+学习双验证、对抗测试 |
| 渲染器偏差 | 状态对但画面错 | 多后端、感知指标、人工评估 |
| 数据泄漏 | 测试集见过 | 按场景/角色/剧集划分 |

## 9. 算力与时间表

| 阶段 | GPU 周（H100） | 日历时间 | 备注 |
| --- | --- | --- | --- |
| Stage A | 8–24 | 3 周 | 可先用小模型 |
| Stage B | 8–16 | 2 周 | 仿真为主 |
| Stage C | 4–8 | 2 周 | 标注瓶颈 |
| Stage D | 4–8 | 2 周 | 规则冷启动 |
| Stage E | 8–32 | 4 周 | rollout 成本 |
| Stage F | 24–64 | 4 周 | 蒸馏 |
| 合计 | 56–152 GPU 周 | ~4 个月 | 不含渲染推理 |

> 渲染推理是持续成本，需单独预算；按每秒生成成本 × 交互时长估算。

## 10. 复现与版本

- 每个训练运行记录：代码 commit、数据版本、超参、随机种子、GPU 型号。
- 模型/状态/渲染器/canon 四个版本号必须一起记录在 `provenance`。
- 评测报告附在 `docs/02-design/experiments/`（后续创建），不覆盖历史。
- 任何“提升”必须同时报告回归测试结果，避免负向迁移。
