## 0. 摘要

**PWM（Persistent World Model，持久世界模型）** 是一个以**显式、持久、可编辑的状态**为核心的世界模型系统。它不把世界状态藏进视频 token，而是把状态提升为第一等公民：

```text
世界状态（World State Graph）
   ├── 结构化层：实体、关系、规则、叙事 canon
   ├── 连续层：位姿、几何、材质、外观
   ├── 记忆层：事件日志、有效时间版本、分支
   └── 不确定层：每个实体的置信度
        │
        ├── System-1 潜空间动力学：快速、动作条件、多尺度预测
        ├── System-2 验证与规划：不变量检查、反事实、修复、重规划
        └── 渲染器抽象：视频扩散 / 3DGS / 游戏引擎，可插拔
```

三个核心判断：

1. **世界模型的价值是可干预的预测，不是像素逼真。** 一个能回答“如果我改变这个条件，未来会怎样”的粗糙模型，比一个只会续写漂亮视频的模型更有用。
2. **长时程一致性需要显式持久状态，而不是更大的上下文窗口。** 上下文会衰减、会被重写；状态可以检查、回滚、分支。
3. **没有单一模型能同时做到物理精确与语义泛化。** 因此采用双系统：快速神经动力学 + 慢速验证/规划，并用渲染器把状态呈现为观测。

PWM 的差异化不在于“再训一个视频模型”，而在于**状态层、验证层与可插拔渲染层的系统设计**。首个垂直场景选择**交互式叙事/短剧**：它的状态结构化程度高、物理精度要求适中、长时程一致性是核心痛点，且能直接衔接现有内容管线。

## 1. 目标与非目标

### 1.1 目标

| 编号 | 目标 | 可衡量标准 |
| --- | --- | --- |
| G1 | 持久、可编辑、可回滚的世界状态 | 任意时刻可导出/导入状态；支持分支与回滚；10 次重访身份保持率 > 85% |
| G2 | 动作条件的多尺度预测 | 语义/物理/编辑三类动作均可条件化；动作敏感度显著高于无条件基线 |
| G3 | 运行时验证与修复 | 物理违规率 < 5/100 帧；canon 矛盾率 < 5%；矛盾可定位到实体/规则 |
| G4 | 渲染器无关 | 同一状态可被视频模型、3DGS、引擎三种后端渲染 |
| G5 | 可交互 | 首版 5–10 fps；目标 15 fps（参考 Frameboy） |
| G6 | 领域可迁移 | 叙事垂直跑通后，接口可复用到机器人/驾驶/游戏 |

### 1.2 非目标

- **不从头训练通用视频基础模型**。使用开源/商用骨干（Cosmos、V-JEPA、开源视频模型、Atlas API）。
- **不在第一阶段解决通用机器人操作**。物理精度按叙事需求设定，不追求接触/形变/流体。
- **不追求全身多智能体照片级物理**。角色交互先做状态/关系/意图层。
- **不做通用 3D 重建产品**。3D 表示服务于状态与渲染，不追求测绘级精度。
- **不承诺“完全自动”**。允许人类在关键节点提供 canon、纠正与审批。

### 1.3 成功标准（项目级）

12 个月内：

1. 一个可演示的交互式叙事世界：跨 10 集保持角色/场景/世界观一致；
2. 一个开源的评测 harness：FlipTest/WMEval 风格的状态与反事实测试；
3. 至少两篇论文/技术报告：状态表示与验证闭环；
4. 与现有短剧管线集成，单位分钟成本可接受。

## 2. 背景与关键假设

### 2.1 来自调研的关键事实

1. 视频世界模型在状态跟踪上系统性失败（FlipTest：11 个模型，最佳 18.3%）。
2. 显式/结构化状态正在回归（Physical Registry、Frame First、GameWM、Atlas spatial context）。
3. WAM 证明“预测未来”与“输出动作”可以共享表征（Cosmos 3、GE-Act 2.0、InternW0）。
4. 长时记忆需要区分“最新”与“有效”（Old Is Not False）。
5. 实时性依赖蒸馏/缓存/异步，是架构约束而非后期优化（Frameboy、Causal-rCM、WorldPlay）。
6. 评测必须状态级、反事实、可回归（WMEval、FlipTest、TetraState）。

### 2.2 关键假设与失效条件

| 假设 | 如果假设不成立 |
| --- | --- |
| A1：显式状态能显著提升长时程一致性 | 退回“视频 + 记忆”方案，验证层仍可保留 |
| A2：叙事动作可以离散化/结构化 | 改用连续潜动作 + 人类标注，成本上升 |
| A3：现成视频渲染器足以支撑叙事镜头 | 自研/微调渲染器，周期与算力增加 |
| A4：验证规则可由领域专家维护 | 改用学习型 verifier，需大量标注 |
| A5：5–10 fps 足以支撑首版交互 | 降级为“离线生成 + 交互式预览” |

### 2.3 约束

- **算力**：以 8–32 张 H100 为阶段预算，推理成本是主要约束。
- **数据**：现有短剧资产（剧本、角色设定、分镜、视频）是冷启动优势；互联网视频用于预训练/先验。
- **时间**：12 个月到可演示；每 6–8 周一个决策门。
- **合规**：演员肖像、剧本版权、生成内容溯源必须从第一天记录。

关键设计原则：**状态拥有真理，渲染器只负责呈现。** 这与 Genie/Sora 的“视频即世界”相反，也是 PWM 可验证、可编辑、可回滚的根源。

| --- | --- | --- | --- |

| **LDE 潜动力学** | 快速动作条件预测 | 冻结视觉编码器 + Transformer 预测器 | 多尺度、WAM 联合训练 |

| **IL 交互层** | API、工具、人类审批 | REST/CLI + 可视化 | 编辑器、协作、权限 |

## 4. 形式化定义

### 4.1 状态

\[
S_t = (G_t,\ \Phi_t,\ M_t,\ U_t)
\]

- \(G_t=(V_t,E_t,A_t)\)：实体-关系图。\(V_t\) 是角色、道具、场景、镜头；\(E_t\) 是关系（知道、拥有、位于、因果）；\(A_t\) 是属性（性格、目标、状态）。
- \(\Phi_t\)：连续状态。每个实体的 6-DoF 位姿、速度、几何（点/高斯/网格）、材质、关节、外观嵌入。
- \(M_t\)：记忆与 canon。长期事实、世界规则、事件日志、目标、有效时间版本。
- \(U_t\)：每个实体/因子的不确定性（identity、pose、dynamics、canon）。

### 4.2 动作

\[
a_t = (a^{phys}_t,\ a^{sem}_t,\ a^{edit}_t)
\]

- \(a^{phys}\)：物理/运动控制（角色走位、物体移动、相机运动）。
- \(a^{sem}\)：语义事件（角色说某句台词、发现秘密、进入场景、时间跳跃）。
- \(a^{edit}\)：编辑操作（改设定、换演员、调光线、重写某场戏）。

叙事场景的优势：\(a^{sem}\) 与 \(a^{edit}\) 是离散/结构化的，绕开了连续机器人动作的数据瓶颈。

### 4.3 转移

\[
\begin{aligned}
G_{t+1} &= f_{struct}(G_t, a^{sem}_t, a^{edit}_t) \\
\Phi_{t+1} &= f_{phys}(\Phi_t, a^{phys}_t) + f_{res,\theta}(z_t, a_t) \\
M_{t+1} &= f_{mem}(M_t, G_t, a_t) \quad \text{(append-only + valid-time)} \\
U_{t+1} &= f_{unc}(U_t, G_t, \Phi_t, a_t)
\end{aligned}
\]

潜变量快路径：

\[
z_t = E_\phi(O_{\le t}),\qquad z_{t+1}\sim p_\theta(z_{t+1}\mid z_t,a_t),\qquad \hat{S}_t = D_\psi(z_t)
\]

状态更新按贝叶斯滤波：

\[
bel(S_t) \propto p(o_t\mid S_t)\int p(S_t\mid S_{t-1},a_{t-1})\,bel(S_{t-1})\,dS_{t-1}
\]

- **预测步**：LDE 给出先验；
- **校正步**：观测编码器/验证器给出似然；
- **门控**：当 \(U_t>\tau\) 时，请求新观测、调用 System-2，或回退到视频先验。

### 4.4 训练目标

\[
\mathcal{L} =
\lambda_1 \mathcal{L}_{latent}
+\lambda_2 \mathcal{L}_{obs}
+\lambda_3 \mathcal{L}_{phys}
+\lambda_4 \mathcal{L}_{inv}
+\lambda_5 \mathcal{L}_{cal}
+\lambda_6 \mathcal{L}_{struct}
+\lambda_7 \mathcal{L}_{task}
\]

| 项 | 作用 | 备注 |
| --- | --- | --- |
| \(\mathcal{L}_{latent}\) | JEPA 式潜空间预测 | 目标编码器 stop-grad |
| \(\mathcal{L}_{obs}\) | 渲染/重建（采样帧） | 不要求每帧都解码 |
| \(\mathcal{L}_{phys}\) | 穿透、守恒、接触、平滑 | 可用仿真/几何检查 |
| \(\mathcal{L}_{inv}\) | 逆动力学一致性 | 从状态对预测动作 |
| \(\mathcal{L}_{cal}\) | 不确定性校准（NLL） | 避免过度自信 |
| \(\mathcal{L}_{struct}\) | 身份、图结构、canon 一致性 | 规则/对比学习 |
| \(\mathcal{L}_{task}\) | 下游任务/策略 | 规划成功率、生成质量 |

## 5. 关键机制

### 5.1 物体中心、变化优先的状态

**问题**：完整未来监督会被静态背景主导（ResWAM）；全局场景表征会淹没局部交互（LaST0.5）。

**设计**：

- 每个实体有稳定 ID 与局部坐标系；预测以**增量**为主：\(\Delta \Phi_t\) 而非 \(\Phi_{t+1}\)。
- 用物体初始位姿的 SE(2)/SE(3) 坐标系表达输入输出（参考 Frame First：决策遗憾降低 1.9–2.2 倍）。
- 预测头分两路：**不变因子**（身份、材质、外观）与**变化因子**（位姿、关系、状态）。
- 实体重识别：外观嵌入 + 几何 + 记忆检索，三路融合。

### 5.2 多时间尺度

| 尺度 | 时间 | 预测内容 | 实现 |
| --- | --- | --- | --- |
| 微观 | 10–100 ms | 接触、运动、相机 | 物理/几何 + 残差网络 |
| 中观 | 秒–分钟 | 事件、动作、镜头 | Transformer 动力学 |
| 宏观 | 分钟–小时 | 任务、剧情、canon | System-2 + 事件日志 |

跨尺度一致性通过约束实现：宏观事件不能违反微观物理；微观变化必须能解释宏观状态转移。

### 5.3 动作条件化

- **物理动作**：连续向量/轨迹，来自引擎或人类控制。
- **语义动作**：结构化事件（主体、谓词、客体、时间），用文本/图嵌入编码。
- **编辑动作**：对状态图/ canon 的直接操作，带事务语义。
- **潜在动作适配器**：对无动作视频，用逆动力学/潜在动作码提供弱监督（Genie/OnlyAct 思路）。
- **动作敏感度损失**：显式惩罚“不同动作给出相同预测”，防止动作条件塌缩。

### 5.4 运行时验证与修复

这是 PWM 与现有视频世界模型最大的区别：**验证不是离线 benchmark，而是运行时循环的一部分。**

```text
预测 S_t+1
   → 检查不变量 I(S_t+1)
       ├── 通过 → 输出/渲染
       └── 失败 → 定位矛盾（实体/规则/尺度）
                  → 修复（投影/重规划/请求观测）
                  → 重新验证
                  → 记录矛盾到事件日志
```

不变量示例：

| 类型 | 例子 | 检查方式 |
| --- | --- | --- |
| 对象永久 | 角色 A 不能凭空消失 | 实体 ID 连续性 |
| 身份 | 角色 A 的脸/服装不能变 | 外观嵌入距离 + canon |
| 空间 | 两个实体不能占据同一空间 | 几何碰撞 |
| 物理 | 物体不能悬浮/穿透 | 物理引擎/守恒 |
| 因果 | 未发生的 event 不能成为因 | 事件图可达性 |
| 叙事 | 角色不能知道自己未经历的事 | 知识状态图 |
| 风格 | 镜头/光线不能跳变 | 渲染一致性 |

修复策略按代价排序：

1. **状态投影**：把状态投影到约束流形（最小改动）。
2. **局部重预测**：只重算受影响的实体/时间窗。
3. **重规划**：System-2 改变动作序列。
4. **请求观测**：人类/传感器提供新信息。
5. **回退**：使用上一可靠 checkpoint，标记不确定性。

### 5.5 记忆、版本与分支

**事件溯源（event sourcing）**：世界状态不是可变对象，而是“初始状态 + 事件日志”的折叠结果。好处：

- 任意时刻可重建；
- 可审计“为什么变成这样”；
- 分支只需复制日志前缀。

**双时间（bitemporal）**：

- **有效时间**：事实在世界中何时为真；
- **记录时间**：我们何时知道/修改它。

这直接解决 Old Is Not False 的问题：撤销动作后，“最新记录”可能描述的是过去的状态；必须按有效时间而非记录时间检索。

**分支树**：

```text
checkpoint@t0
  ├── branch A: 角色 X 说出真相
  │     └── rollout 20 steps → 验证 → 评分
  ├── branch B: 角色 X 隐瞒
  │     └── rollout 20 steps → 验证 → 评分
  └── 选择/合并（人类审批或自动评分）
```

这使“what-if”成为一等能力，而不是重新生成整段视频。

### 5.6 渲染器抽象

```text
interface Renderer {
  render(state: WorldState, camera: Camera, style: Style): Observation
  capabilities(): { resolution, fps, modalities, control }
  cost(estimate): { latency_ms, gpu_seconds }
}
```

三种后端：

| 后端 | 适用 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 视频扩散 | 叙事镜头、风格化 | 画质/泛化 | 慢、状态弱 |
| 3DGS/NeRF | 空间场景、重访 | 几何一致、实时 | 动态弱 |
| 游戏引擎 | 精确布局、交互 | 状态精确、可控 | 资产/真实感 |

**混合模式**：引擎输出粗布局/深度/遮罩 → 视频模型精修。参考 GameWM 与 Interactive Cosmos。

### 5.7 实时路径

```text
用户输入
  → 动作编码 (2ms)
  → System-1 增量预测 (10-20ms)
  → 验证快检 (5ms)
  → 渲染（蒸馏少步 / 缓存）(30-50ms)
  → 输出
```

- System-2 异步运行，不阻塞交互；发现矛盾时发“修正补丁”。
- 目标：首版 5–10 fps；优化后 15 fps（720p）。
- 优化手段：少步蒸馏（Causal-rCM）、控制感知缓存（CtrlCache）、分层渲染（低分辨率预览 + 按需精修）。

## 6. 数据与训练

### 6.1 数据金字塔

| 层级 | 数据 | 用途 |
| --- | --- | --- |
| L1 | 互联网视频 | 视觉/运动先验；无动作自监督 |
| L2 | 仿真/游戏 | 动作标签、物理真值、反事实 |
| L3 | 现有短剧资产 | 领域先验、角色/场景 canon、镜头风格 |
| L4 | 人类交互日志 | 编辑偏好、纠错、分支选择 |
| L5 | 标注数据 | 实体/关系/事件/矛盾标签 |

### 6.2 训练阶段

| 阶段 | 目标 | 数据 | 产出 |
| --- | --- | --- | --- |
| **A. 自监督预训练** | 视觉编码器 + 潜动力学 + 物体槽 | L1 + L2 | 可预测的潜空间 |
| **B. 动作条件** | 物理/语义动作条件化 | L2 + L3 + 少量 L3 标注 | 动作条件动力学 |
| **C. 结构化状态** | 实体图、关系、canon 抽取 | L3 + L5 | WSG 抽取器 |
| **D. 验证/修复** | 不变量检查、矛盾定位、修复策略 | L2 + L5 + 合成矛盾 | 验证器 + 修复器 |
| **E. 想象中 RL** | 在模型中优化动作/镜头 | L2 + 模型 rollout | 规划器/策略 |
| **F. 实时蒸馏** | 少步渲染、缓存 | 教师模型 | 实时渲染器 |
| **G. 持续学习** | 从交互日志更新 | L4 | 版本化模型 |

### 6.3 课程

1. 单场景、短时程、单实体；
2. 多实体、遮挡、重访；
3. 动作条件（走位/物体移动）；
4. 语义事件与对话；
5. 长时程（10+ 分钟）、多场景；
6. 分支/反事实/retcon；
7. 多集/多季 canon。

### 6.4 算力估算（量级）

| 阶段 | 估算 | 说明 |
| --- | --- | --- |
| Phase 0 | 1–2 张 GPU | 基线复现、评测 harness |
| Phase 1 | 4–8 张 H100 × 4 周 | 小规模动力学训练 + 推理 |
| Phase 2 | 8–16 张 H100 × 8 周 | 领域微调 + 渲染器适配 |
| Phase 3 | 16–32 张 H100 × 12 周 | 长时程、蒸馏、服务 |
| 持续 | 8–16 张 H100 | 推理与迭代 |

> 估算假设：使用开源/商用骨干，不自研基础视频模型；渲染推理占大头。

### 7.1 可证伪假设

## 8. 与现有方案的差异

| 维度 | Genie 3 / Sora 2 | V-JEPA 2 / Dreamer | Cosmos 3 | Marble / Atlas | GameWM | **PWM** |
| --- | --- | --- | --- | --- | --- | --- |
| 状态 | 隐式视频 token | 隐式潜变量 | 隐式/多模态 | 显式 3D 空间 | 引擎显式状态 | **显式图 + 连续 + 记忆** |
| 可验证 | 弱 | 中（潜空间） | 中 | 几何可验证 | 规则可验证 | **运行时多类不变量** |
| 可编辑/回滚 | 弱 | 弱 | 弱 | 中 | 强（引擎） | **强（事件溯源 + 分支）** |
| 长时记忆 | 数分钟 | 短 | 中 | 持久空间 | 引擎保证 | **bitemporal + 分支** |
| 动作 | 潜在/文本 | 机器人 | 多模态 | 相机 | 游戏动作 | **物理/语义/编辑三类** |
| 叙事 canon | 无 | 无 | 无 | 无 | 无 | **核心** |
| 渲染 | 视频 | 无/解码 | 视频 | 3DGS | 引擎+视频 | **可插拔** |

**核心新颖点**：

1. 把“世界状态”从生成模型中解耦，做成持久、可版本化、可分支的图；
2. 把验证器做成运行时组件，而不是离线指标；
3. 用 bitemporal 记忆处理撤销/retcon/回访；
4. 用语义动作/编辑动作绕开机器人动作数据瓶颈；
5. 渲染器无关，允许视频/3D/引擎混合。

**与最接近工作的关系**：

- **Physical Registry**：提供了“状态槽”的模型内实现；PWM 把它提升为系统级状态层，并加入记忆/分支/验证。
- **GameWM**：验证了“引擎保状态 + 视频生成内容”的分工；PWM 把这一模式推广到非游戏领域，并给出通用状态 schema。
- **Atlas**：提供了 spatial context 与可插拔 3D 输出；PWM 增加动态、语义、canon 与验证。
- **Cosmos 3**：最强的开放骨干；PWM 可作为其上层状态/验证系统，而非替代。

## 9. 首个垂直：交互式叙事世界模型（INWM）

### 9.1 为什么选叙事/短剧

| 维度 | 叙事/短剧 | 机器人 | 驾驶 |
| --- | --- | --- | --- |
| 状态结构化 | 高（角色/道具/场景/关系） | 中 | 中 |
| 物理精度要求 | 中低 | 高 | 高 |
| 动作数据 | 可用离散事件/编辑 | 昂贵 | 中等 |
| 长时程一致性 | **核心痛点** | 重要 | 重要 |
| 人类评估 | 可行 | 困难 | 危险 |
| 现有资产 | **有**（剧本/角色/分镜） | 少 | 少 |
| 商业闭环 | 内容生产 | 远期 | 中期 |

### 9.2 映射

| PWM 概念 | 叙事实例 |
| --- | --- |
| 实体 \(V\) | 角色、道具、场景、镜头 |
| 关系 \(E\) | 亲情、敌对、知道秘密、拥有物品 |
| 连续状态 \(\Phi\) | 走位、姿态、外观嵌入、光线、相机 |
| 记忆 \(M\) | 世界观圣经、角色小传、前集剧情、伏笔 |
| 物理动作 | 走位、转身、拿起、镜头运动 |
| 语义动作 | 说台词、发现、背叛、时间跳跃 |
| 编辑动作 | 改设定、换演员、重写场景、调色 |
| 渲染器 | 图生视频/首尾帧、3DGS 布局、引擎预览 |
| 验证器 | canon 矛盾、身份、空间连续、因果、风格 |

### 9.3 演示场景

1. **跨集一致性**：生成第 2 集，自动检查与第 1 集 canon 的矛盾。
2. **交互式 what-if**：用户改一个事件（“如果她没有说出真相”），系统分支 rollout、评估后果、只重生成受影响的镜头。
3. **多集记忆**：角色外观、关系、已知信息在 10 集后仍正确。
4. **镜头级控制**：指定机位、走位、光线，渲染器执行。
5. **Retcon**：修改过去的一个设定，系统沿依赖图传播影响，标记需要重拍的镜头。
6. **协作**：编剧/导演在状态层编辑，渲染器按需出片。

### 9.4 成功指标

| 指标 | 目标 |
| --- | --- |
| 跨 10 集 canon 矛盾率 | < 5% |
| 角色身份保持（人工/嵌入） | > 90% |
| 人类偏好 vs 基线 | > 60% 胜率 |
| 单分钟生成成本 | 低于传统重拍/动画的 30% |
| 交互延迟 | 首版 < 200ms/帧（5 fps），目标 66ms（15 fps） |
| 编剧任务时间 | 降低 ≥ 40% |

## 10. 风险与缓解

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 状态抽取误差累积 | 高 | 高 | 不确定性门控；人工校正；回退到视频先验 |
| 混合架构复杂度失控 | 高 | 中 | 先做两层（图 + 潜动力学），物理后置 |
| 渲染器不可控/成本高 | 中 | 高 | 多后端；首版用现成视频模型；成本上限 |
| 评测主观/不可复现 | 中 | 高 | 规则指标 + 人类评估 + 回归测试 |
| 数据/版权问题 | 中 | 高 | 数据卡、授权记录、合成数据、水印 |
| 团队精力分散 | 高 | 高 | 垂直优先；每阶段一个决策门 |
| 基础模型快速迭代 | 高 | 中 | 渲染器/编码器可插拔；不锁定单一供应商 |
| “看起来能做”但下游无用 | 中 | 高 | 以 L2 效用为验收，不以 demo 视频为验收 |

## 12. 开放问题

1. 状态 schema 能否跨领域复用，还是每个垂直一套？
2. 验证规则的人工维护成本是否会随领域爆炸？
3. 语义动作的离散化粒度如何选择？
4. 渲染器与状态的误差如何归因？
5. bitemporal 记忆的存储/检索成本？
6. 如何评估“叙事质量”而不只评估一致性？
7. 人类在环的最佳介入点在哪里？
8. 分支数量增长时如何管理（剪枝/评分/回滚）？
9. 如何避免 verifier 被策略“钻空子”？
10. 跨模态（文本/图像/视频/3D）状态如何统一？
