## 1. 一句话结论

**存储正在从大模型的"后台设施"变成"第一性约束"：推理的瓶颈是每 token 要搬多少 KV，训练的瓶颈是每几分钟要写多少 checkpoint，而这两件事都由存储层次决定，不由算力决定。**

这句话不是修辞。把 70B 模型、128K 上下文、batch=32 的数代进去，KV 约 **1.25 TiB**，需要约 10 张 H200 仅用于放 KV（按 141 GB 口径）；而 decode 每生成一个 token 都要把这些字节过一遍，H100 的 roofline 拐点是 295 FLOP/B，GQA-8/FP16 的 decode 算术强度上界只有 **8 FLOP/B**——差 37 倍。这意味着无论 batch 怎么调，长上下文 decode 都不可能变成 compute-bound。**它不是"算得慢"，是"搬得慢"。**

## 2. 问题的物理起源：四个不可回避的定量事实

完整的推导与算例见 `raw/analysis-quant.md`，这里只列结论。

### 2.1 KV 的体积由架构决定，不由参数量决定

$$
k = \frac{2Ldb}{r}\ \text{bytes/token}
$$

- 70B（Llama-3 型，GQA-8，BF16）≈ **320 KiB/token**；128K 上下文单请求 ≈ **40 GiB**；
- 405B（GQA-16）≈ 504 KiB/token；
- 671B MoE + MLA（DeepSeek-V3）≈ **68.6 KiB/token**，反而比 405B dense 小 7.3 倍。

**含义**：容量规划不能用"参数量 × 系数"。同一参数量下，注意力结构（MHA/GQA/MLA/滑动窗口）可以让 KV 差一个数量级。

### 2.2 Decode 的算术强度上界与模型规模无关

$$
I_{\text{dec}}^{\infty} = \frac{2r}{b}
$$

GQA-8/FP16 只有 8 FLOP/B，而 H100 BF16 的拐点约 295 FLOP/B。**模型变大不会改善这个比值；上下文变长也不会。** 唯一能改变它的是架构（提高 $r$、MLA）与精度（降低 $b$）。

### 2.3 Prefill 与 decode 相差 3–4 个数量级

Prefill 在 32K 上下文时算术强度约 $3\times10^4$ FLOP/B，是 compute-bound；decode 是 memory-bound。这不是工程偏好，而是 PD 分离的物理必然性。

### 2.4 Checkpoint 是权重的 8 倍，且是突发负载

Adam 混合精度状态约 **16 B/param**：70B ≈ 1.12 TB，671B ≈ 10.7 TB。按 Young/Daly，最优间隔是分钟级；671B 在 3.6 秒写完时峰值写带宽约 **3 TB/s**，而平均只有 39 GB/s——**峰均比约 77×**。按平均带宽规划 checkpoint 存储会低估两个数量级。

> **这四个事实共同解释了为什么"存储服务大模型"不是把现有存储做得更快，而是要为一种新的数据对象（KV）和一种新的写入模式（checkpoint 风暴）重新设计接口。**

## 3. 技术图谱：生命周期 × 存储职能

我们把大模型的数据对象按**生命周期**与**存储职能**两个维度展开。每个格子里的代表工作见括号。

| 生命周期 \ 职能 | 容量 | 带宽/延迟 | 元数据/索引 | 一致性/版本 | 隔离/安全 | 成本/寿命 |
|---|---|---|---|---|---|---|
| **数据准备**（天–月） | 数据湖、对象存储 | 并行读、GDS | 样本级 lineage | 数据集 MVCC | 多租户配额 | 去重、压缩 |
| **预训练**（周–月） | 3FS/vePFS/Lustre | checkpoint 突发写 | manifest/原子提交 | 快照一致性 | 作业隔离 | SSD 寿命、能耗 |
| **后训练/RLHF**（天–周） | 多版本权重、rollout 数据 | 高吞吐读写 | adapter/轨迹索引 | 版本回滚 | 实验隔离 | 存储放大 |
| **模型分发**（月–年） | 模型仓库 | 冷启动加载 | 内容寻址/CDC | 不可变/签名 | 供应链安全 | 去重率 |
| **Prefill**（秒） | KV 复用池 | 前缀读、RDMA | radix/哈希链 | **复用契约** | 缓存侧信道 | 命中率 ROI |
| **Decode**（毫秒） | HBM/DRAM | 每 token 全量读 | 块表 | 活跃请求不可淘汰 | 租户干扰 | 能耗/token |
| **多轮/Agent**（分–时） | 会话 KV、记忆 | 追加写、随机读 | 时间/实体索引 | **事务/遗忘** | 记忆投毒 | 写放大 |
| **评估/可观测**（持续） | trace、指标 | 低 | 指标定义 | 可复现 | 审计 | — |

**读法**：横向看是"同一职能在不同生命周期的形态"；纵向看是"同一阶段需要哪些存储能力"。**空白格**出现在右下角：Agent 阶段的一致性/隔离、Prefill 阶段的复用契约、评估阶段的标准化指标——这三格是 `04-研究方案提案.md` 的主要来源。

## 4. 九个研究簇与演进脉络

### 4.1 KV 分层与卸载：从"放不下"到"放哪层"

**脉络**：PagedAttention [arXiv:2309.06180] 把 KV 变成可分页的块 → FlexGen [arXiv:2303.06865] / ZeRO-Inference 证明 CPU/SSD 可以换吞吐 → InfiniGen [arXiv:2406.19707] 用稀疏预取把"全量搬"变成"按需搬" → LMCache [arXiv:2510.09665] 把 KV 抽成跨引擎的缓存层 → Mooncake [arXiv:2407.00079] 把 KV 池做成数据中心级对象 → Tutti [arXiv:2605.03375] / FlatCake [arXiv:2610.38355] 让 GPU 直控 SSD、让 DRAM 与 SSD 对等。

**当前 SOTA 的隐含假设**：DRAM 一定在 SSD 之前做时间过滤。FlatCake 用生产负载的双峰分布推翻了这个假设：要么一次性超长复用距离，要么数 GB 的 agent 会话超过 DRAM 容量，DRAM 过滤双双失效。

**未解**：对象粒度税（Range [arXiv:2610.21241]：同样 6 GiB，192 个对象 2.1 s，6,144 个对象 3.0 s）、SSD 寿命（Gandalf [arXiv:2610.30791]）、远端命中的尾延迟（[arXiv:2610.21500] 报告远端命中 0.88 s vs 重算 0.31 s）。

### 4.2 KV 压缩与稀疏：收益进入平台期

**脉络**：StreamingLLM [arXiv:2309.17453] 的 attention sink → H2O / Scissorhands 的 heavy-hitter 驱逐 → SnapKV [arXiv:2404.14469] 的观察窗口 → Quest [arXiv:2406.10774] 的 query-aware 页稀疏 → KIVI [arXiv:2402.02750] 的 2-bit 量化 → MLA 的架构级压缩 → KVTC [arXiv:2511.01815] 的 20× 变换编码。

**关键判断**：H2O/SnapKV 一类报告在保留约 20%（约 5×）时精度基本不变（H2O 的 20% heavy-hitter 设置即属此列 [arXiv:2306.14048]），但这不是长期平台——KV² 在 RULER 16K 上报告 2% 预算（约 50×）[arXiv:2610.03198]，KVpop 报告 75%/88% 压缩且保留 98%/97% [arXiv:2607.05061]，Lexico 仅用 15–25% 内存并保持 90–95% 性能 [arXiv:2412.08890]；检索/多跳任务上掉点仍然明显；量化与编码的"压缩比–精度"前沿高度重合，单设备短上下文下 FP4 与 Polar 串联未见叠加收益（[arXiv:2610.33076] 在两个维度都劣于单用 FP4）。**真正的杠杆已经转向架构级（GQA/MLA）与存储级（可检索 KV、量化格式），而不是又一个驱逐策略。**

### 4.3 前缀与非前缀复用：正确性问题浮出水面

**脉络**：vLLM APC / SGLang RadixAttention 的严格前缀哈希 → CacheBlend [arXiv:2405.16444] 的跨块融合 → CacheTune [arXiv:2605.24022] 指出非前缀直接复用会破坏全局注意力 → KVBoost [arXiv:2608.21362] 用"位置哈希 + 内容哈希"双键 → SAFE-KV [arXiv:2610.15186] 用因果后缀修复。

**最重要的数字**：SAFE-KV 报告，前缀条件下拼接只保留 HotpotQA-500 的 **47.2%**、2Wiki-500 的 **37.8%** 全量 prefill 答案；风险引导修复后回到 **99.8%/98.4%**。这说明"复用"不是缓存命中问题，而是**语义等价性问题**。

**未解**：存储层没有 API 表达"我接受 ε 误差，请给我最便宜的 KV 版本"；缓存 key 通常不含模型版本、tokenizer、LoRA adapter、量化配置、RoPE scaling。

### 4.4 PD 解耦与调度：收益取决于 SLO，跨论文数字不可比

**脉络**：Orca 的连续批处理 → DistServe [arXiv:2401.09670] / Splitwise [arXiv:2311.18677] 的 prefill/decode 分离 → Llumnix [arXiv:2406.03243] 的动态重调度 → Sarathi-Serve [arXiv:2403.02310] 的 chunked prefill → Mooncake 的 KVCache-centric 全局调度。

**现状**：PD 分离已是事实标准，但收益高度依赖 SLO、模型与负载：DistServe 在自身 TTFT/TPOT 约束下报告 7.4× 请求率 [arXiv:2401.09670]，Splitwise 以吞吐/成本口径报告 1.4× [arXiv:2311.18677]，两者不可拼成一条“收敛”曲线；下一波竞争在 **KV-aware routing** 与全局 KV 目录，而不是再拆一次 prefill/decode。

### 4.5 训练数据与文件系统：LLM 训练几乎不耗数据带宽

**脉络**：Lustre/GPFS → 3FS（DeepSeek，2025 开源）用 FoundationDB 做元数据、CRAQ 链式复制、全链路 RDMA → 字节 vePFS、Meta Tectonic 同构。

**反直觉事实（一阶估算，假设 3000 tok/s/GPU、4–16 B/token，推导见 raw/analysis-quant.md §5）**：1024 GPU 的 LLM token 流聚合只有 **12–50 MB/s**；真正打爆存储的是**元数据**（2000 sample/s/GPU × 1024 × 4 ops ≈ 820 万 ops/s）与 **checkpoint**（比数据加载高 10³–10⁵ 倍 bytes/FLOP）。把"LLM 训练存储瓶颈"归因于"数据读不动"是常见错误。

### 4.6 Checkpoint：从"写文件"到"可重分片数据集"

**脉络**：CheckFreq 的动态间隔 → Gemini 的内存检查点 → ByteCheckpoint [arXiv:2407.20143] 的并行度无关格式 → TierCheck [arXiv:2605.17821] 的本地/对等/远端三层 → AccelPact [arXiv:2609.18178] 的零 I/O 恢复。

**2026 新方向**：checkpoint 不再只是容错原语，而是被选择、合并、审计、甚至电网调度共同消费的一等数据对象。AccelPact 测到每步异步检查点仍有 **+656.7%** 延迟、32.5 GiB 主机内存、3.39 TB/hour 流量——"异步"不等于免费。

### 4.7 模型分发：内容寻址与 CDC 去重

**脉络**：safetensors 成为事实标准 → ServerlessLLM [arXiv:2401.14351] 用近端存储做快速加载 → HuggingFace Xet 用内容定义分块去重 → TensorCast [arXiv:2608.06007] 提出"张量生命周期即服务"。

**未解**：模型变体爆炸（base + LoRA + 量化 + 不同 tokenizer）带来的存储放大；跨变体的 KV 复用（KVShareArena [arXiv:2609.10266] 指出跨 checkpoint 复用会掉质量）。

### 4.8 向量检索与 RAG：从"建索引"到"更新与迁移"

**脉络**：DiskANN（NeurIPS'19，无 arXiv）/ SPANN [arXiv:2111.08566] 把图索引放到 SSD → CAGRA 用 GPU 加速 → RemoteANN [arXiv:2610.25172] 把向量检索原生化到对象存储 → Puffin [arXiv:2606.04196] 把 ANN 索引挂到 Iceberg 表上。

**未解**：embedding 版本迁移（10 亿 × 768 × 4B ≈ 3.07 TB；全量重建约 3 TB 量级（估算，含索引与中间态倍数）、过滤检索、多租户、增量更新写放大。**索引的"更新成本"比"查询延迟"更接近真实痛点。**

### 4.9 Agent 记忆：把 R0 数据当缓存设计

**脉络**：MemGPT 的虚拟上下文 → Mem0 的抽取式记忆 → GEM [arXiv:2605.26252] 把记忆定义为"状态轨迹"而非记录 → ChronoMem [arXiv:2607.27773] 的版本化 + 自然语言回滚 → Bemula [arXiv:2610.18052] 把遗忘变成一等评测。

**核心矛盾**：Agent 记忆是 **R0（不可重建）** 数据，但现有系统普遍按 **R1 缓存** 设计——没有事务、没有溯源、没有删除传播。2026 年的安全评测已经把后果量化：记忆库中 84.7% 的必需应用能检出他人凭证，压力测试下 80–94% 的运行会使用他人凭证 [arXiv:2610.25707]。

## 5. 技术演进时间线（2020–2026）

```
2020 ── Orca 连续批处理；ZeRO 把优化器状态分片
2021 ── ZeRO-Infinity 把 NVMe 纳入内存层级；CheckFreq 动态 checkpoint
2022 ── FlashAttention（IO-aware）；FlexGen 单卡 offload；Pond CXL 池化
2023 ── ★ PagedAttention/vLLM 把 KV 变成可分页对象
        StreamingLLM、H2O 开启 KV 压缩；safetensors 成为标准
2024 ── DistServe/Splitwise/Llumnix/Sarathi 完成 PD 分离与调度
        InfiniGen/CacheGen/CacheBlend/CachedAttention 打通 KV 存储路径
        Mooncake（FAST'25）把 KV 池做成数据中心级
2025 ── LMCache 开源；3FS 开源；KV 量化进入 2-bit
        ServerlessLLM、ByteCheckpoint 成熟；Agent 记忆开始系统化
2026 ── ★ 对象粒度税被量化；SSD 寿命成为一等约束
        Tutti/FlatCake 让 GPU 直控 I/O、DRAM 与 SSD 对等
        SAFE-KV/KVBoost 把非前缀复用的正确性显式化
        CXL-SSD/光子 CXL/HBF 进入原型；混合注意力使前缀缓存抽象失效
        缓存侧信道攻击被证实可达 100% 成功率
```

**拐点判断**：2023 年是"KV 成为存储对象"，2026 年是"**KV 的正确性与寿命成为存储问题**"。前者是容量危机，后者是治理危机。

## 6. 空白格：几乎没有人做的组合

| 空白 | 为什么重要 | 现有工作为何不覆盖 | 对应方案 |
|---|---|---|---|
| **KV 复用契约** | 复用错误是静默故障 | 研究多关注命中率/加速比，不定义"可复用"的语义 | P1、P4 |
| **KV 的 SSD 寿命模型** | 写入量可在数月耗尽 SSD | 存储论文假设 SSD 无限耐久；系统论文不建模 TBW | P3 |
| **GPU 直控 I/O 的 QoS** | 多租户下 GPU 发起 I/O 会互相干扰 | Tutti 等只做单租户性能 | P2 |
| **Agent 记忆的事务语义** | R0 数据 + 多写者 + 合规删除 | 记忆论文多研究检索算法，不研究 ACID/隔离 | P6 |
| **Checkpoint 的控制面** | manifest/GC/跨集群/原子提交 | 研究异步/增量机制，不研究"checkpoint 数据库" | P7 |
| **模型供应链存储** | 变体爆炸 + 供应链安全 | 工业界用 CDC，学术界几乎不研究 | P8 |
| **KV 存储基准** | 跨论文数字不可比 | 无标准 trace/指标；MLPerf Storage 不覆盖推理 KV | P9 |
| **CXL-SSD 的设备语义** | 现货 CXL-SSD 不比 NVMe 快 | 器件论文与系统论文脱节 | P10 |
| **混合/线性注意力的状态存储** | 状态不可回滚到任意前缀 | 前缀缓存假设 token 可寻址 | P11（探索） |
| **视频 latent/素材的存储层** | 对象布局、版本化、时序索引、训练数据管道缺失（视频记忆机制已有研究，见 2.15） | 存储层仍处早期 | P12（探索） |

## 8. 与相邻领域的关系

- **数据库**：向量索引、LSM、MVCC、GC 的直接迁移；Agent 记忆本质是"带语义索引的事务库"。
- **体系结构**：CXL、HBM、CSD、PIM 决定"哪些层存在"；存储系统决定"怎么用"。
- **网络**：RDMA/NVLink/光子互连决定"数据能多快到达"；拓扑感知已成为存储放置的一等输入。
- **ML 系统**：调度、批处理、并行策略决定"存储看到什么访问模式"；二者必须联合设计。
- **安全/合规**：缓存侧信道、记忆投毒、删除传播，正在从"事后审计"变成"存储原语"。
