# 基准测试、Trace 与工作负载刻画

## 1. 问题定义与为什么它是存储问题

这个方向的核心矛盾是：AI 系统真实产生的存储压力，与用来驱动存储选型和调优的代理指标之间，存在系统性错位。合成基准压的是峰值带宽与 IOPS，回放器重放的是采集到的训练 I/O，但两者都不执行真实框架操作，也不复现研究型负载"突发、异构、元数据密集"的形态 [arXiv:2607.21746v2]。错位的代价很直接：采购与调优在优化一个不存在的负载。

三条路径把它变成存储问题。其一，推理侧的 KV cache 与 prefix 复用，把"命中率"变成跨 HBM/DRAM/NVMe/对象存储的分层放置问题——生产 trace 显示 agentic 编码会话在单个 turn 内 KV cache 命中率平均 90%，跨 turn 边界跌至 55%，模型切换或上下文压缩后进一步失效（论文声称）[arXiv:2608.00101v1]。其二，训练与科研负载的访问模式从"少数大文件的顺序读写"转为"跨大量随机文件的小读" [arXiv:2404.10386v3]，元数据路径取代峰值带宽成为瓶颈。其三，数据集本身的容量与物理布局直接决定检索成本：对象存储上不同布局的差异最终反映为传输字节数与美元 [arXiv:2607.28880v1]。

关键指标因此被改写：研究者迭代速度而非峰值吞吐 [arXiv:2607.21746v2]；TTFT/TBT 的完整分布与 P99 [arXiv:2610.37989v1]；单次查询的传输字节与金钱成本 [arXiv:2607.28880v1]；KV 命中率与跨 turn 复用率 [arXiv:2608.00101v1]；以及模型自身的误差（IOPS 4–10%、延迟 3–16%）[arXiv:2307.02073v2]。

## 2. 技术流派

### 2.1 生产 trace 采集与生成器

核心思想：放弃合成负载，从真实服务采集请求级 trace，再抽象成可参数化重放的生成器，使评测能覆盖长尾、多模态与推理型请求。

**ServeGen** [arXiv:2505.09999v3] 从自有全球云推理服务采集负载，覆盖语言模型以及新兴的多模态与推理模型，指出既有分析在规模与范围上均不足，并据此构建负载生成器。摘要未给出量化结果（900 字符截断），也未说明生成器保真度指标。局限：单一厂商、闭源服务形态，难以复现跨租户干扰。

**Agentic Coding in the Wild** [arXiv:2608.00101v1] 首个生产规模的 agentic 编码 trace 刻画，采样 2026 年 6 月 GitHub Copilot 数据，含 320 万用户、1300 万会话、7.61 亿次 LLM 调用、95 万亿 token。机制上把会话拆成稀疏的用户 turn，每个 turn 展开为几乎总与工具执行耦合的自主 agent 循环。结论是 KV 命中呈现两个区间：turn 内平均 90%，跨 turn 55%，且模型切换、上下文压缩会显著使其失效（论文声称）。局限：单一产品、采样偏差，只含 token 与调用级信息、不含字节级 I/O。

**RAGPulse** [arXiv:2511.12979v1] 开源 RAG 负载 trace，来自 2024 年 4 月起服务逾 4 万师生的校内问答系统，采用隐私保护的哈希数据格式，并指出通用 LLM trace 无法刻画"检索—生成"两阶段与知识依赖。摘要未给量化结果。

共同假设：请求级 trace 足以代表存储压力。失效场景：trace 缺少缓存状态与字节级访问，无法直接驱动块层/文件层设计；生成器容易抹平长尾。

### 2.2 真实负载驱动的存储基准

核心思想：让基准执行真实应用与真实框架操作，而不是只压合成 I/O；把"通过基准"当作新存储上线的资格门。

**PRISM** [arXiv:2607.21746v2] 覆盖 AI 科研的六个阶段：版本控制、环境搭建、数据准备、数据加载、checkpoint、合成数据生成，全部跑真实框架操作。它明确对比三类现状：合成工具只压峰值带宽与 IOPS，模拟器只重放训练 I/O，二者都不执行真实操作。指标是研究者迭代速度。摘要未给数值结果。局限：绑定 POSIX 语义，场景偏科研集群。

**LayoutBench** [arXiv:2607.28880v1] 首个针对多媒体数据的云存储布局基准，比较三种布局：每样本独立对象（L1）、顺序打包为 tar（L2）、组织为 Parquet 列（L3）；在 ImageNet 上用 11 条不同结果集大小的查询，跨六个 AWS 环境（摘要此处截断）测检索时间、传输数据量与金钱成本。局限：只覆盖对象存储与图像类数据。

**MLPerf HPC** [arXiv:2110.11466v2] 由 MLCommons Association 驱动的端到端科学 ML 训练基准套件，首轮提交覆盖多台世界最大规模 HPC 系统，并给出系统化的评分方法。局限：更新周期长，存储被当作黑盒，不单列 I/O 阶段耗时。

**列存格式实证评估** [arXiv:2304.05028v3] 重新拆解 Parquet 与 ORC 的内部实现，设计基准在不同负载配置下压测性能与空间效率，指出字典编码等决策在现代硬件与真实数据分布下更有利（摘要截断）。局限：停留在格式层，不涉及放置与调度。

**I/O in ML Applications on HPC: A 360-degree Survey** [arXiv:2404.10386v3] 综述 2019–2024 六年文献，给出关键判断：ML 负载是"跨大量随机文件的小读"，与传统 HPC 的大块访问相反，对并行存储构成新挑战。局限：综述无新测量。

共同假设：把真实应用跑一遍即可代表存储压力。失效场景：跨租户干扰、缓存预热状态、元数据规模常被隐去。

### 2.3 解析建模、统计建模与仿真器

核心思想：用排队论、解析模型或 ML 回归替代昂贵实测，预测吞吐/延迟分布，支撑配置搜索与容量规划。

**Predictive Modeling of I/O Performance for ML Training Pipelines** [arXiv:2512.06699v2] 跨 NVMe SSD、NAS、内存文件系统做系统性基准，收集 141 组观测，覆盖底层 I/O 与完整训练流水线；比较 7 个回归模型与 3 类分类方法，XGBoost 最优，R²=0.991，吞吐预测平均误差 11.8%；特征重要性显示吞吐指标与 batch size 是主因。文中称 GPU 常因等数据而空闲在 50% 利用率以下（论文声称）。局限：观测规模小、单机后端，外推到集群存储存疑。

**Performance Modeling of Data Storage Systems using Generative Models** [arXiv:2307.02073v2] 把 HDD/SSD 池、不同 RAID 与 cache 各组件表示为概率模型，刻画其 IOPS/延迟分布，构成数字孪生；误差为 IOPS 4–10%、延迟 3–16%，与 Little 定律预测的 Pearson 相关最高 0.99（论文声称）。局限：配置空间有限，未覆盖并行文件系统。

**MIST** [arXiv:2504.09775v6] 异构多阶段 LLM 推理执行模拟器，建模 RAG、KV 检索、推理、prefill、decode 跨硬件层级，并支持异构客户端并发多模型；动机是穷举配置的云成本可超 40K（摘要未注明币种）。局限：保真度取决于标定，存储层被简化。

**GAUSS** [arXiv:2610.37989v1] 面向 fleet 的解析加蒙特卡洛模拟器，预测 TTFT 与 TBT 的完整分布及可持续请求率；用 prefill/decode 分段延迟面加 Lindley 递推刻画连续批处理下的排队。其核心论点是：聚合吞吐在尾延迟恶化之前早已饱和。局限：需按引擎与加速器逐一对标定。

**inference-fleet-sim** [arXiv:2603.16054v1] 用 M/G/c 排队加离散事件仿真，求满足 P99 TTFT SLO 的最低成本 fleet 配置；内置 A10G/A100/H100 的物理性能模型，覆盖单体、双池路由、分离式三种拓扑。局限：网络与存储参数化，未实测。

**LIFE** [arXiv:2508.00904v1] 硬件与数据集无关的算子级解析框架，可刻画量化、KV cache 压缩、LoRA、chunked prefill、算子融合对 TTFT 等指标的影响。摘要未给出量化结果。

共同假设：服务时间分布可标定、系统处于稳态。失效场景：突发到达、跨租户干扰、缓存冷启动、存储侧尾延迟。

### 2.4 评测方法论批判

核心思想：先审计基准本身，再谈结论；评测错误会系统性地高估系统收益。

**On Evaluating Performance of LLM Inference Serving Systems** [arXiv:2507.09019v1] 归纳三类反模式：Baseline Fairness、Evaluation Setup、Metric Design，并指出 prefill/decode 双阶段、异构负载、交互式严格时序使这些反模式在 LLM 场景格外有害，例如不充分的 baseline 会把工程效率混同为算法收益。摘要未给量化数据。

**DNA LM shuffling** [arXiv:2510.12617v2] 是"数据管线参数污染基准"的直接证据：dataloader worker 数与 buffer size 这类硬件相关超参，会让同一模型在 BEND 上产生最高 4% 的虚假性能差异，根因是 shuffle 不足与领域数据特性交互；实验覆盖 HyenaDNA、DNABERT-2、ResNet-LM。对存储的启示是：数据供给参数本身就是基准的一部分。

共同假设：基准的可复现性由代码保证。失效场景：硬件相关超参与缓存状态天然不可移植。

### 2.5 刻画驱动的系统闭环

核心思想：把刻画结果直接接回调度、缓存与架构搜索，形成"测量—决策—再测量"的闭环。

**Hydra** [arXiv:2608.25053v1] 统一 schema 的 phase-aware 刻画框架，给 HuggingFace Transformers 与 llama.cpp 打同一套 per-prompt 打点并与硬件遥测融合；覆盖三代边缘 SoC（AGX Xavier、AGX Orin、AGX Thor）、13 个指令微调 LLM（7 个族）、5 种执行格式，产出约 10.7 万条记录并公开。价值在于把 prefill/decode 的延迟、内存流量与能效拆开。

**DriftSched** [arXiv:2606.02982v2] 指出多租户 GPU 推理中"准入时的负载估计"与运行时实际不符（token drift），导致误分类、队列失衡与尾延迟上升；组合工作负载分类、token 预算估计、租户感知队列与在线反馈。局限：NVIDIA L4 单卡类环境，摘要截断未给收益数字。

**ACPC** [arXiv:2512.14151v1] 针对 LLM 推理高度不规则、突发的访问，用 TCN 学习 token 访问序列的时间依赖以识别高复用 cache line，再用优先级感知替换策略抑制 cache pollution。局限：摘要止于机制，未给命中率或延迟收益。

**RoofLang** [arXiv:2609.12551v2] 用 DSL 提供通用工作负载表示、可验证变异空间与实现无关评估器，使 AI 能参与推理系统架构搜索；评估称 DeepSeek V4 系列峰值 decode 吞吐可比其他代表模型高 3.5–39.5 倍，差距主要来自紧凑的 KV cache 设计而非总参数量（论文声称）。

共同假设：在线信号可得且足够快。失效场景：信号采集本身要走存储与网络，反而引入抖动。

### 2.6 数据侧存储成本基准

核心思想：把"训练数据占多少容量"当作可优化目标，用蒸馏、压缩、选择性保留换取存储与传输节省。

**Vector-Quantized Soft Label Compression** [arXiv:2603.03808v1] 指出数据集蒸馏中每个合成样本关联多个软标签，在 ImageNet-1K 等大类场景软标签是存储成本的主要贡献者，并给出各数据集的比特需求分析。摘要未给压缩比。

**DRIP** [arXiv:2504.08364v2] 用 Grad-CAM 在线打分决定样本保留或丢弃，四个数据集上精度匹配甚至超过全量训练，存储节省最高 39%（论文声称）。

**低比特量化语音表示** [arXiv:2301.00652v1] 1-bit 量化下存储减少 86.32%（184.42→25.23），估计运行时减少 88%（1.00→0.12），WER 由 7.06 升至 15.96（论文声称）。

**DC-Bench** [arXiv:2207.09639v2] 数据集蒸馏的首个系统评测基准，指出数据增强与模型架构会掩盖压缩方法的真实差异。

**StarCraft II 序列化框架** [arXiv:2410.08659v1] 针对 RTS 回放这类复杂结构数据设计序列化，降低创建与存储成本并对标 AlphaStar-Unplugged。摘要未给数字。

共同假设：存储成本可用"删/压"线性换精度。失效场景：审计、复现与法规留存要求原始数据。

其他工作一句话：GRIEF [arXiv:2605.11202v1] 用灰盒模糊测试把带时序的多请求 trace 当一等输入，在 vLLM/SGLang 上发现 15 个漏洞（10 个已确认，摘要截断）；BVLSM [arXiv:2506.04678v2] 主张在 WAL 阶段完成键值分离以缓解大 value 引起的写放大与 I/O 抖动；MemoryOS [arXiv:2506.06326v1] 把 agent 记忆做成短期/中期/长期三级存储单元并定义更新与检索操作；Intelligent Router [arXiv:2408.13510v2] 按 prefill/decode 阶段差异做集群级路由；TIDE [arXiv:2602.05145v2] 复用目标模型隐状态在线适配草稿模型；Power Trace Generation [arXiv:2603.18383v1] 用"状态转移 + 状态内功率分布"合成站点级功率轨迹。

## 3. 2025–2026 最新进展

- **从合成压测转向真实操作与真实 trace**。PRISM 直接把合成工具与回放器列为不足；agentic 编码 trace 首次达到生产规模（95 万亿 token）。基准的角色也从"评分"变成"资格门"。
- **负载原型从 chatbot 换成 agent**。多步 LLM 调用与工具执行交织，KV 复用在 turn 内（90%）与 turn 间（55%）出现两个数量级不同的区间，并新增"模型切换""上下文压缩"两类缓存失效事件 [arXiv:2608.00101v1]。
- **评测对象从单引擎上移到 fleet**。MIST、GAUSS、inference-fleet-sim 都在做容量与 SLO 规划，说明瓶颈从 kernel 上移到跨池路由与存储分层。
- **指标从均值转为分布**。TTFT/TBT 分布与 P99 成为主指标，因为聚合吞吐在尾延迟恶化前就已饱和 [arXiv:2610.37989v1]。
- **模型架构反过来成为存储变量**。RoofLang 显示 KV cache 紧凑度可带来 3.5–39.5 倍 decode 吞吐差，"KV 怎么放"已是架构级决策 [arXiv:2609.12551v2]。
- **基准自身被审计**。反模式清单、dataloader 超参造成 4% 虚假差异，以及云对象存储布局被纳入成本模型 [arXiv:2507.09019v1][arXiv:2510.12617v2][arXiv:2607.28880v1]。

## 5. 对存储系统设计的启示

1. **把"跨 turn 前缀复用率"做成一等遥测与放置键**。既然 turn 内命中 90%、跨 turn 只有 55%，存储层应按 session/turn 血缘组织 KV 对象，并让模型切换、上下文压缩触发显式失效 RPC，而不是等 LRU 自然淘汰 [arXiv:2608.00101v1]。
2. **checkpoint 与数据准备要当作独立 I/O 阶段设计**。PRISM 把 checkpoint、环境搭建、版本控制拆成阶段，意味着需要 chunk 级增量 checkpoint、异步落盘与去重，而不是一个大文件覆盖写 [arXiv:2607.21746v2]。
3. **元数据路径优先于带宽**。科研负载是"大量随机小读" [arXiv:2404.10386v3]，接口上应提供批量 stat/open、扁平命名空间与目录分片，SLO 用"迭代速度/首次结果时间"表达，而非 GB/s。
4. **把布局做成可查询的接口而非静态约定**。L1/L2/L3 的成本随查询结果集大小变化 [arXiv:2607.28880v1]，存储应暴露布局建议与下推能力（tar 区间读、Parquet 谓词下推），让检索成本与查询共同优化。
5. **容量规划用分布而非均值**。以 P99 TTFT/TBT 为目标做 fleet 与缓存层配比，因为聚合吞吐在尾延迟恶化前就已饱和 [arXiv:2610.37989v1][arXiv:2603.16054v1]。
6. **数据集压缩要计入软标签与增强副本**。软标签在 ImageNet-1K 级任务中是存储主因 [arXiv:2603.03808v1]，存储成本模型若只算原图会系统性低估。

## 6. 必读五篇

1. **Agentic Coding in the Wild** [arXiv:2608.00101v1]——唯一给出生产规模 agent 会话结构与 KV 命中双区间的 trace 工作，直接定义了新的缓存放置问题。
2. **PRISM** [arXiv:2607.21746v2]——把"基准即资格门"讲得最清楚，并给出 AI 科研六阶段的真实操作清单。
3. **ServeGen** [arXiv:2505.09999v3]——生产 LLM 服务负载刻画与生成器的方法论范本。
4. **LayoutBench** [arXiv:2607.28880v1]——把"数据怎么摆"量化为时间/字节/美元三轴，是存储布局研究少见的成本视角。
5. **On Evaluating Performance of LLM Inference Serving Systems** [arXiv:2507.09019v1]——读任何加速比之前应先读的反模式清单，避免被不公平 baseline 误导。
