# 2025–2026 存储服务大模型：从"放得下"到"搬得动、修得对、写得少"

## 一、十一条可验证的趋势

**1. 瓶颈单位从"字节"变成"对象"。** 决定 TTFT 的不再是搬多少 GiB，而是一次恢复要触碰多少个逻辑对象。同样 6 GiB KV，切成 192 个对象恢复需 2.1 s，切成 6,144 个对象则需 3.0 s，且逐层加载后更差——查找、分配、提交 I/O、送 GPU、写回、索引每一层都按对象计费 [arXiv:2610.21241]。GPU 显存碎片化会产生海量微小随机 I/O，即使启用 GDS，CPU 仍要为每次 I/O 介入 [arXiv:2605.03375]；语义级细粒度选 token 与粗粒度定长 I/O 块不匹配，则直接变成读放大 [arXiv:2601.13631]。

**2. 远端/共享缓存层的收益被条件化，"命中一定更快"不再成立。** 在 GLM-5.3（FP8 MoE + MLA）的 8×B300 上开启远端层，中位 TTFT 不变，但 16k token 的 p99 从 3.96 s 涨到 17.3 s；一次远端命中耗时 0.88 s，而重算 prompt 只要 0.31 s；同步加载把命中密集的流变成不稳定队列，p99 达 83.32 s 而 GPU 只有 7% 忙 [arXiv:2610.21500]。KVStream 进一步指出节点已挂载的并行文件系统"几乎不承载推理流量"，静态分层策略必然偏离聚合带宽上界 [arXiv:2610.31827]；更早的 Cake 已把问题表述为"算还是读"的联合调度 [arXiv:2410.03065]。

**3. SSD 寿命从脚注升格为一等约束。** 多轮对话与 agent 负载下，KV 累计写入量显著超过 SSD 容量，寿命从"数年"缩短到"数月" [arXiv:2610.30791]；急切持久化所有块会迅速耗尽耐久度，而 GPU 服务器上 SSD 数量有限又限制了重载带宽 [arXiv:2610.31169]。HBF 场景同样发现 LRU 把写入与 miss 耦合，产生过量写流量 [arXiv:2609.07175]。反过来，前缀感知去重能显著削减写量，但前提是页缓存仍然温热——一旦被逐出，同一路径在 683 ms 内发出约 1 GB 顺序读 [arXiv:2610.21249]。

**4. 严格分层被"对等介质 + 扁平地址空间"取代。** 生产负载呈双峰：要么是一次性、复用距离极长的块，要么是超过 DRAM 容量的多 GB agent 会话，DRAM 的时间过滤作用双双失效，于是把 host DRAM 与 NVMe 暴露为统一 64 位地址空间下的对等介质 [arXiv:2610.38355]。TempoKV 用"元数据认领 + 到期提交"解耦"知道会复用"和"占用快层"，避免过早预留 [arXiv:2609.35065]；LM-CXD 直接把 KV chunk 做成设备可见的 I/O 单元 [arXiv:2609.26828]；ITME 则用 CXL-hybrid 内存把 JBOF/DPU 的 NVMe-oF 路径统一成共享上下文层 [arXiv:2606.12556]。

**5. 前缀缓存从"严格前缀"扩展到"任意位置段复用"。** CacheTune 明确指出传统前缀缓存只适用于严格前缀，非前缀直接复用会破坏跨 chunk 的全局注意力 [arXiv:2605.24022]；KVBoost 用"位置哈希 + 内容哈希"双哈希键把复用从位置约束中解放出来 [arXiv:2608.21362]；SparseX 以连续 token 段为复用单元并在单次前向内做稀疏重算 [arXiv:2606.01751]。需求侧证据很硬：agent memory 负载中，落在匹配前缀之外的重复记录占注入 token 的 70% 以上 [arXiv:2609.32999]。

**6. "复用无损"被推翻：存在容忍集，保真度不等于可用性。** 冻结的 transformer 只能读取接近"它自己会写出"的缓存，这个区域被称为 tolerable set；与该缓存的几何相似度并不能预测读者能否使用它，且失败不是渐进的——因此"更忠实的替代品"并不是解法 [arXiv:2610.22016]。SAFE-KV 给出量化证据：前缀条件下拼接只保留 HotpotQA-500 的 47.2%、2Wiki-500 的 37.8% 全量 prefill 答案，风险引导修复后可回到 99.8%/98.4% [arXiv:2610.15186]。在 5% 重算预算下，文档对齐重算把跨请求顺序的答案波动从 69.0% 降到 26.1% [arXiv:2610.05833]；多 agent judge 场景中复用会系统性削弱跨候选注意力 [arXiv:2601.08343]。

**7. GPU 开始直控 I/O，CPU 退出关键数据路径。** Tutti 把 KV 做成 GPU 侧对象存储，CPU 只负责异步控制，从而消除 HBM↔SSD 路径上的 CPU 介入 [arXiv:2605.03375]；DUAL-BLADE 按运行时空闲内存动态分配 page-cache 路径与 NVMe-direct 路径，后者把 KV 张量映射到连续 LBA 区域以绕过文件系统 [arXiv:2604.26557]；DAK 复用 TMA 把远端内存中的权重与 KV 直接搬入 SMEM，绕开预取造成的 HBM 争用 [arXiv:2604.26074]。但 Range 的结论是必要的冷水：把每对象工作从 CPU 移到 GPU，工作本身仍然是每对象的 [arXiv:2610.21241]。

**8. CXL 从"扩内存"走向"可组合共享池 + 近内存计算"，但现货性能不达预期。** Beluga 让 GPU 与 CPU 共享大规模内存池 [arXiv:2511.20172]；512 GiB CXL 设备可在 95.4%–99.5% 外部命中率下把跨节点 TTFT 降低 5.5×–36.6× [arXiv:2609.10790]；光子 CXL 用无源光纤 shuffle 在 16 主机间提供 32 TB 共享内存，相对电气 CXL 池延迟降低逾 50% [arXiv:2607.27187]；1M token 场景把 token 页选择卸载到 CXL 内的 PNM 加速器 [arXiv:2511.00321]。然而现货 CXL-SSD 比本地 DRAM 慢约 3×，且并不比 NVMe SSD 更快，通用预取几乎无收益 [arXiv:2609.26828]；CXL 链路与设备侧 DDR 带宽远低于 HBM，必须靠压缩才能维持解码 [arXiv:2509.03377]。

**9. 对象存储进入 KV 关键路径。** ObjectCache 把 KV 放进 S3 兼容对象存储，让容量不再是约束，代价是必须协同设计存储协议与传输调度，使服务端按 GPU 消费顺序交付数据，并在 100 Gbps RoCE + NIXL 上把传输与计算重叠 [arXiv:2605.22850]。跨区域场景则出现新问题：KV 缓存由服务请求的 worker 现场创建，持有者集合随请求与逐出而变化，因此 KV 发现"在结构上比传统对象查找更难"，需要把 KV 身份与放置解耦 [arXiv:2610.24179]。

**10. 混合/线性注意力让"前缀缓存"这一抽象本身失效。** 全注意力 KV 可按 token 寻址，而线性注意力层维护的 recurrent state 无法回滚到任意前缀边界，现有系统只能物化检查点，把复用限制在离散边界 [arXiv:2609.33477]；Tail-Replay 把 Gated DeltaNet 视作对前缀的结构化有损压缩来绕开该限制 [arXiv:2608.30310]；HiState 面向 agent 负载管理分层检查点，避免检查点挤占其他会话的可复用前缀 [arXiv:2610.41508]。更隐蔽的是调度层：匹配到前缀不代表状态已就绪，消费者会被阻塞并产生"执行气泡" [arXiv:2610.18143]；PIC 与混合注意力的原语也无法直接共存 [arXiv:2607.01299]。

**11. Agent 负载把缓存策略从"最近最少使用"改成"会话生命周期 + 指令化"。** Continuum 为工具调用间隙引入 KV 的 time-to-live [arXiv:2511.02230]；Cache Engineering 让 agent 直接用 drop 等原语控制活动缓存，而不修改轨迹、不重新 prefill [arXiv:2610.28577]；Leyline 主张引擎应暴露"删除/替换某段缓存并继续"的一等原语 [arXiv:2606.01065]。同时出现"recency synchronization"：LRU 会集中逐出少数 agent 的私有历史，造成 TTFT 长尾 [arXiv:2609.32278]。跨模型复用开始成形：base 与 LoRA 适配模型之间通过 base 对齐块哈希复用前缀 [arXiv:2512.17910]，多 LoRA agent 用 copy-on-write 物理解耦 KV [arXiv:2604.06370]，异构模型间则以低秩子空间 + 稀疏补丁替代原始 KV 传输 [arXiv:2606.07684]。

**12. 缓存成为安全边界。** 多租户共享前缀缓存构成时间侧信道，PROMPTPEEK、EarlyBird、InputSnatch 三类攻击对未防护的 vLLM/SGLang 成功率可达 100% [arXiv:2608.09225]；对真实 API 的统计审计在包括 OpenAI 在内的七家提供商中检测到跨用户全局缓存共享 [arXiv:2502.07776]；API 网关层还可能绕过提供商级隔离 [arXiv:2605.30613]；语义缓存则面临投毒与键碰撞攻击 [arXiv:2608.01718][arXiv:2601.23088]。

## 二、被打破的 2023–2024 假设

| 旧假设 | 反证 |
|---|---|
| KV 只能在 HBM/DRAM，SSD 是最后手段 | 6 GiB KV 从 SSD 恢复 2.1–3.0 s 已进入 TTFT 关键路径 [arXiv:2610.21241]；S3 对象存储被直接用作 KV 层 [arXiv:2605.22850] |
| 前缀缓存只服务严格前缀 | 段级/位置无关复用成为独立赛道 [arXiv:2605.24022][arXiv:2608.21362][arXiv:2610.13060] |
| SSD 只做容量层，容量换成本 | 写入量超容量、寿命年→月，写策略成为设计中心 [arXiv:2610.30791][arXiv:2610.31169] |
| 远端/共享层总比重算快 | 远端命中 0.88 s vs 重算 0.31 s，p99 恶化 4×以上 [arXiv:2610.21500] |
| 命中即正确，复用是保真度问题 | 存在 tolerable set，几何相似度不能预测可用性 [arXiv:2610.22016][arXiv:2610.15186] |
| DRAM 做 SSD 的前置缓存，LRU 逐出即可 | 双峰复用使 DRAM 时间过滤失效 [arXiv:2610.38355]；14 种驱逐算法相对 LRU 收益甚微 [arXiv:2609.28870] |
| 缓存优化是纯性能问题 | 侧信道可达 100% 攻击成功率 [arXiv:2608.09225] |

## 三、2026 年才出现的新问题

1. **SSD 寿命与写放大的联合优化**：既要降写量又不能降命中率，还要在 SSD 数量受限时保住重载带宽 [arXiv:2610.30791][arXiv:2610.31169]。
2. **CXL-SSD 名不副实**：字节可寻址并未自动带来收益，需把 KV chunk 语义下沉到设备 [arXiv:2609.26828]，并靠压缩弥补链路带宽 [arXiv:2509.03377]。
3. **GPU 直控 I/O 后的"对象粒度税"**：绕过 CPU 解决了发起开销，但没有解决对象数随上下文、层数、TP 并行度相乘的问题 [arXiv:2610.21241]。
4. **对象存储 KV 的协议耦合**：必须让存储侧按消费顺序交付，否则 TTFT 无法收敛 [arXiv:2605.22850]；跨区域还要解决"KV 位置随请求漂移"的发现问题 [arXiv:2610.24179]。
5. **跨模型/跨 checkpoint 复用**：base↔LoRA、多 LoRA、base↔微调之间存在语义漂移，逐层累积 [arXiv:2512.17910][arXiv:2606.07684][arXiv:2604.06370]。
6. **状态不可回滚**：混合注意力与扩散 LLM 的缓存都不是 token 可寻址的，双向表示还会在去噪中变化 [arXiv:2609.33477][arXiv:2610.39853]。
7. **复用正确性缺少度量**：现有评测方法会系统性高估复用效果，数据集也缺乏真实复用动态 [arXiv:2609.31415]。

## 四、真实趋势与论文噪声

**真实趋势**（有硬件约束或生产 trace 支撑）：对象粒度问题 [arXiv:2610.21241][arXiv:2605.03375]、SSD 寿命 [arXiv:2610.30791]、非前缀复用 [arXiv:2609.32999]、CXL 池化 [arXiv:2609.10790]、混合注意力破坏缓存抽象 [arXiv:2609.33477]。

**趋同/噪声区**：

- **KV 量化与编码**：KVTC 报 20×（特定场景 40×+）[arXiv:2511.01815]，DCKV 报 55×–100× 但代价是 1.8–3.6 个点 [arXiv:2610.36950]，GAAC 走无损路线只有 1.405× [arXiv:2610.38210]。方法各异而"压缩比—精度损失"前沿高度重合；更关键的是组合并不叠加：FP4 与 Polar 串联后 4,241 B/token、15.1 tok/s，在两个维度上都劣于单用 FP4 [arXiv:2610.33076]。
- **驱逐策略**：两家公司生产 trace 上 14 种算法相对 LRU 提升有限，原因是前缀复用被活跃会话的规律节奏主导，recency 异常有效 [arXiv:2609.28870]；20 种混合负载下没有单一最优策略，LRU 在 agent 密集场景比 S3FIFO 高 12%，在其他场景低至 22% [arXiv:2610.36355]。真正有信息量的是"按 token 类型区分"（复用率差异达 756×）[arXiv:2605.18825]，而不是又一个 LRU 变体。
- **计算存储**：早期主张把整个 attention 下沉到 CSD [arXiv:2409.04992]，现在退化为"只把轻量 token 重要性判定放到单块 SmartSSD"，因为在一块弱 CSD 上做精确 attention 会耗尽 FPGA 资源 [arXiv:2602.18750]；ReFlux 直言静态卸载"脆弱"——设备侧处理器在持续热负载下降频，且没有计算存储平台实现规模化部署 [arXiv:2604.02442]。
- **语义缓存**：论文数量多，但分水岭是能否给出错误率保证 [arXiv:2502.03771]，否则只是命中率数字游戏。

## 结语

2025–2026 年的主线不是"KV 终于能放到 SSD 上"，而是**存储栈的计费单位、正确性定义和安全边界同时被重写**：从字节到对象，从命中到可用，从性能到耐久与隔离。可以据此判断一个新系统论文是否值得读——它是否给出了对象数、写入量或修复成本中的至少一个新约束；如果只是又一个基于 LMCache/vLLM 的命中率提升，那多半落在噪声区。
