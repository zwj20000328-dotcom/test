# 模型权重存储、加载与分发

## 1. 问题定义与为什么它是存储问题

核心矛盾是权重的增长速度超过单卡 HBM 容量的增长速度，而权重在一次服务周期内是只读的、跨实例高度重复的、并且必须按层或按专家被按需取用。一旦服务形态从"一模型一卡"变成多模型目录、多租户与 serverless 弹性伸缩，权重就不再只是计算数据，而成为需要被放置、复制、去重、预取和回收的持久状态。综述性工作 [arXiv:2610.33475v1] 把这条链路概括为 HBM wall、prefill（计算密集）与 decode（带宽密集）的运维不对称、KV cache 膨胀、serverless 冷启动与硬件可靠性五类瓶颈，并指出既有综述把加速器虚拟化、集群编排与运行时推理割裂开来看。

它之所以是存储问题，有三个判据。其一，冷启动延迟随模型大小线性增长 [arXiv:2512.01357v1]，权重加载直接落在关键路径上。其二，decode 阶段每 token 的字节搬运量由权重与 KV 共同决定，驻留位置决定吞吐上限。其三，多个实例各自驻留同一份权重造成显存放大，共享与去重于是变成容量问题 [arXiv:2610.25219v1]。对应的关键指标不是一个延迟数字，而是：冷启动/TTFT、有效驻留率（被共享或复用的权重字节占比）、单位 token 的存储→HBM 搬运量、加载带宽利用率，以及 KV 这类"第二类状态"的落盘收益比。

## 2. 技术流派

### 2.1 Serverless 冷启动：分层加载与流水线重叠

核心思想：承认权重必须从远端搬来，但把它拆成可并行、可多播的块，在传输途中就开始计算，并用 GPU 显存、主机 DRAM、远端存储构成的多层缓存压缩有效路径。

- [arXiv:2512.01357v1] Tangram: Accelerating Serverless LLM Loading through GPU Memory Reuse and Affinity。用 GPU 上空闲显存保留模型参数，构造统一 GPU 内存池做张量级跨模型参数共享，配合按需 KV 分配与 GPU 亲和性调度。机制上是"把闲置显存当作权重缓存层"。摘要未给出量化结果（900 字符处截断）。
- [arXiv:2502.09922v3] λScale。GPU 节点间用 RDMA 做模型多播，并允许 execute-while-load；λPipe 自适应选择多播方式，并在接收端动态搭建执行流水线，使"传"与"算"共享同一时间窗。摘要未给出量化数字。
- [arXiv:2503.17707v1] PipeBoost。把容错流水线并行同时用于加载与推理，聚合多条 PCIe 带宽；论文声称相比当时的最优低延迟系统降低 31%–49.8% 推理延迟。摘要对 OPT-1.3B 的冷启动结论在"cold-sta"处截断，具体数值摘要未给出。
- [arXiv:2502.20959v2] Cicada。指出流水线仍会因"逐层顺序构建 + 单体权重加载"停顿；MiniLoader 优化参数初始化，WeightDecoupler 把权重文件处理与层构建解耦，实现异步取权重。

综述性报告 [arXiv:2411.15664v1] 复述了 ServerlessLLM 的多层 checkpoint 加载（复用闲置 GPU 显存与存储），声称启动时间降低 6–8x，可作为该流派的基线数字。

共同假设：加载可被建模成一条顺序数据流，且聚合带宽足以把加载隐藏在计算之后。失效场景是模型规模远超单跳带宽窗口、多租户同时冷启动造成网络争抢（HydraServe [arXiv:2502.15524v2] 为此做跨服务器主动分发与 worker 放置）、以及权重必须跨节点保持版本一致的场景。

### 2.2 驻留集最大化：显存复用、去重与多路径

核心思想：与其加速"搬"，不如让"已经搬来的"被更多实例复用，并把驻留层从 HBM 向外扩张。

- [arXiv:2610.25219v1] gKSM。在驱动层做 GPU 内存去重：CPU-GPU 协同哈希管理（哈希计算下放到 GPU kernel），零拷贝的模型权重去重，并在没有原生 copy-on-write 的前提下用写隔离保护共享页。它把去重从应用层拉到内核/驱动层，是"共享页需要写隔离原语"的直接证据。摘要未给出量化结果。
- [arXiv:2605.19481v1] C2CServe。利用 GH200/GB200 的 NVLink-C2C，把权重常驻 CPU 内存、按请求流式送入 MIG 切片，把模型驻留从稀缺 HBM 迁到充裕主机内存，从而在空间共享 GPU 上服务大模型。摘要未给出量化结果。
- [arXiv:2608.13127v2] Potential Applications of HBF in LLM Serving Systems。把 High-Bandwidth Flash 定位为 HBM 的容量型扩展，专门承载"读多写少的模型状态对象"，用扩大的常驻集支持更多专家副本与热模型复制。作者强调收益依赖保留 HBM 上的执行路径，结论来自仿真，摘要未给具体数字。
- [arXiv:2606.23969v2] The Serialized Bridge。反面证据：在 B300 上 BF16 matmul 仍有 0.998x 的非机密性能，但 Intel TDX + GPU-CC 下 LLM 服务吞吐损失 13–27%，KV cache 恢复延迟翻倍以上，小粒度 alloc-and-copy 慢约 44x。原因是机密 VM-GPU 桥把 host/device 搬运变成了串行、高固定开销的通道，破坏了 DMA"廉价、并发、异步"的假设。

共同假设：权重只读、页可共享、搬运便宜。失效场景包括无 COW 时的写隔离、机密计算下的串行通道，以及单 GPU PCIe 路径成为事实上限——MMA [arXiv:2512.16056v2] 用软件定义多路径把一次拷贝拆到直连与中继链路上，说明带宽还有可挖掘空间。

### 2.3 MoE 专家预取与弹性执行

核心思想：MoE 的结构性优势是每次只激活少量专家，只要专家能在计算前到位，offloading 理论上可逼近全量驻留；难点是把"路由之后才知道"变成"路由之前就预取"。

- [arXiv:2609.12978v1] SeqMoE。首次把专家激活预测重构为序列建模（seq2seq），做多层、多步预测以提供足够长的决策窗口；并把预取调度形式化为带截止时间的作业排序（Job Sequencing with Deadlines），以最大化期望专家命中并改善带宽效率。摘要未给出量化结果。
- [arXiv:2607.24787v2] SpecPrefetch。用共享轻量 adapter 只预测"下一层可能需要的专家"，且预测结果仅用于异步传输；真正执行的专家仍由冻结的原始 router 决定。这样把传输预测与执行路由解耦，避免预测误差改变模型输出。摘要未给出量化结果。

同类工作还包括 Remoe [arXiv:2512.18674v1]（非专家留 GPU、专家放 CPU、低频专家下沉为独立 serverless 函数）与 MoEless [arXiv:2603.06350v2]（层感知预测器估计专家负载、提前识别 straggler 并弹性伸缩）。

共同假设：专家激活虽 input-dependent，但短期可预测，预测错误的代价可被带宽冗余吸收。失效场景是分布漂移导致预取污染带宽、预测窗口与 PCIe/NVLink 时延不匹配，以及专家副本放置与函数冷启动耦合。

### 2.4 张量粒度与生命周期抽象

核心思想：把权重、KV、checkpoint 统一看作"有生命周期的张量状态"，用一层抽象把放置、迁移、压缩、回收从计算逻辑里剥离出来。

- [arXiv:2608.06007v1] TensorCast。识别出"张量生命周期管理"是 LLM 基础设施缺失的抽象层，提出 Tensor-as-a-Service：提供 first-class 张量抽象与可编程生命周期，把张量状态管理与计算逻辑解耦，统一覆盖权重加载、KV 管理与 checkpoint 同步。这是最贴近存储系统接口视角的一篇。摘要未给出量化结果。
- [arXiv:2607.10183v2] ATSInfer。批评现有 offloading 只做层级或专家级调度、忽略同层内张量的异质性；改为张量粒度 offloading，静态放置加负载感知的动态迁移，并用异步 CPU-GPU 协调调度存储、搬运与计算。摘要未给出量化结果。
- [arXiv:2406.11674v1] Endor。为剪枝后的非结构化稀疏权重设计硬件友好的稀疏格式，以高压缩比、低解压开销降低权重传输延迟。其 offloaded 推理案例研究给出一个关键事实：权重搬运是绝对瓶颈，实际计算几乎占 0% 运行时。摘要未给出量化结果。

其他压缩与共享路线：在片上内存控制器内对权重与 KV 做 LZ4/ZSTD 无损块压缩 [arXiv:2503.18869v3]；利用模型间共享参数块做多用户调度与带宽分配（PartialLoading [arXiv:2503.22982v2]）；移动端按静态调度流式加载而非全量预加载（FlashMem [2602.15379v1]）。

共同假设：粒度越细、压缩越强，收益单调增长。失效场景是元数据与调度开销、碎片化，以及压缩后仍需随机访问的张量布局。

### 2.5 KV cache 与变体状态：第二类"权重"

核心思想：KV cache 已经从"推理中间态"变成可落盘、可跨上下文/跨 checkpoint 复用的持久对象，其存储语义接近权重，但写入模式与失效条件完全不同。

- [arXiv:2610.10845v1] Real Long-Term Memory for AI。把每约 16,000 token 的 KV 状态作为块写入加密本地 NVMe，之后逐字节精确读回。在 50,000,000 token 真实公开文本、单张 H100、vLLM、Gemma 4 12B/31B 上，探测的 100/100 个块均无需重算即读回；加载比重新计算快 2.8x–4.3x，GPU 能耗低 8.8x–12.3x，整个 50M token 流中 GPU 显存保持平稳。关于"数百万 token 前植入事实"的正确率，摘要只写到"82"即被截断，完整口径摘要未给出。
- [arXiv:2609.10266v2] KVShareArena。指出现有 prefix caching 假设"同一模型 + 完全相同前缀"，而 RAG、多 agent 共享材料、跨 checkpoint 更新都同时打破这两个条件；KV 依赖前缀与权重两者，直接复用会掉答案质量。它提供跨上下文、跨 checkpoint 的基准与开放评测，并指出各方法自定任务、模型与成本口径，无法横比。摘要未给出量化结果。
- [arXiv:2609.39329v2] PatchKV。在上下文加载时用岭回归闭式求解一个上下文相关的权重 patch，使压缩 KV 的块级激活对齐全量 KV；patch 合并进权重后离开前向图，单查询推理成本不变。这是"把 KV 的一部分搬进权重"的反向思路。摘要未给出量化结果。
- [arXiv:2501.11779v2] Glinthawk。两层架构：attention 下沉到低端 Tier 2，使 KV 容量与权重解耦、可独立扩展。论文声称相比 paged attention 基线吞吐提升 5.9x、生成成本降低 2.8x；长序列下 16.3x 吞吐、成本低 2.4x。

补充证据：LRAgent [arXiv:2602.01053v2] 把多 LoRA agent 的 KV 拆成"预训练权重决定的共享基座"与"LoRA 决定的适配器分量"，只共享前者；KIVI [arXiv:2402.02750v2] 指出 KV 加载会让计算核心空转，并用 2bit 非对称量化压缩。

共同假设：KV 是可跨请求、跨实例乃至跨模型版本迁移的冷数据。失效场景是权重版本变化使缓存语义失效、量化精度不可迁移、以及加密通道下小 IO 的固定开销被放大。

### 2.6 变体与请求级缓存

核心思想：真正被反复加载的往往不是基座，而是 adapter、微调变体与重复请求的响应。

- [arXiv:2512.20210v1] Predictive-LoRA。用轻量 LSTM 流量预测器预测 adapter 需求，主动把热 adapter 从主机内存预取到 GPU，论文声称冷启动最多降低 68%；并用类 OS 虚拟内存的分页机制管理 adapter 显存以抑制碎片。摘要未给出更多量化结果。
- [arXiv:2505.14468v2] ServerlessLoRA。把服务状态分成共享 backbone、可复用 variant warm 状态、请求私有状态三层；backbone 只加载一次并以只读方式共享给隔离的 LoRA 函数，再按状态局部性与 GPU 争用做路由。摘要未给出量化结果。
- [arXiv:2510.26835v1] Category-Aware Semantic Caching。按请求类别区分缓存策略：高重复类别命中率 40–60%，低重复或易变类别仅 5–15%；远程检索 30ms，需要 15–20% 命中率才打平，导致 20–30% 生产流量无法缓存。它说明"统一 TTL + 统一阈值"在异构负载下必然失效。

共同假设：请求存在可观的重复性，且变体之间共享大部分权重。失效场景是长尾低重复流量、内容快速过期（分钟级股价 vs 月级代码模式），以及 adapter 数量爆炸后的索引与置换开销。

## 3. 2025-2026 最新进展

三个旧假设被打破。第一，"加载是一次性冷启动问题"被打破：galahad-kv 把 KV 变成可长期驻留 NVMe 的持久对象，TensorCast 直接把张量生命周期当成独立层，热路径从"启动"扩展到"持续驻留、校验与回收"。第二，"去重与共享只能在应用层做"被打破：gKSM 把去重下沉到驱动层，ATSInfer 把调度下沉到张量粒度，说明细粒度元数据正在成为系统接口的一部分。第三，"预测只能在路由之后"被打破：SpecPrefetch 与 SeqMoE 把专家预取前移到执行之前，Predictive-LoRA 把 adapter 预取前移到请求到达之前。

硬件侧出现新的容量层（HBF、NVLink-C2C、GB 级 LLC），但机密计算证明 DMA"廉价、并发、异步"的前提并不总成立 [arXiv:2606.23969v2]。与此同时，评测开始成为独立问题：KVShareArena 明确指出跨上下文、跨 checkpoint 的 KV 复用缺乏统一成本口径。总体趋势是从"优化一次加载"转向"管理一份持续存在、可共享、需校验的模型状态"。

## 5. 对存储系统设计的启示

1. **对象化命名**：把权重、adapter、KV block 统一为带版本的内容寻址对象，key 用 `(model_hash, tensor_name, shard, dtype)` 或 `(model_hash, token_span_hash, precision)`，而不是文件偏移。TensorCast 的 tensor handle 与 galahad-kv 的 16k-token 块本质上是同一接口的两种实例。
2. **按读写模式分层，而非按大小分层**：HBF 的结论是只把 read-mostly 的模型状态放进容量层；KV 这类写一次、易失效、需校验的对象应有独立的过期与校验路径，否则会被权重流量挤占。
3. **预取接口外置**：借鉴 PredictIO [arXiv:2610.12971v1] 把"工作负载预测"与"预取执行"分离，存储栈应暴露内核观测到的访问序列与应用 hint（包括 LLM 运行时的 model-layout metadata），使预测策略可跨工作负载复用，而不是嵌在某个推理引擎里。
4. **共享必须带写隔离原语**：跨实例共享权重页需要引用计数与写时复制语义；没有硬件 COW 时应在页表/驱动层做隔离（gKSM），否则"共享"会退化成拷贝，容量收益归零。
5. **传输面要多路径、可多播**：MMA 表明单 GPU 的 PCIe 路径不是上限，λScale 表明一次读取可服务多个副本；存储客户端应把"一次读、多副本消费"作为一等操作，并在机密计算路径上单独建模串行通道，避免小粒度 IO 触发 44x 级惩罚。
6. **压缩放在正确的层**：控制器内无损块压缩适合带宽敏感路径，权重量化适合容量敏感路径；两者都要求按张量异质性分块（ATSInfer），不能假设层内同质。

2. [arXiv:2502.09922v3] —— RDMA 多播加 execute-while-load，把"传输即执行"确立为冷启动优化的一个范式。
3. [arXiv:2512.01357v1] —— 把 GPU 空闲显存变成跨模型参数共享池，是"驻留集最大化"思路的代表。
4. [arXiv:2609.12978v1] —— 把专家预取从启发式提升为序列预测加截止时间调度，方法上最完整。
5. [arXiv:2608.06007v1] —— 提出张量生命周期作为独立抽象层，最接近存储系统设计者需要的接口定义。
