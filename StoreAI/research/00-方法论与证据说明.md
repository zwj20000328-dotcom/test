> 本文件说明本次调研的问题边界、证据等级、分析框架与已知局限。**建议先读本文件，再读其余报告**，否则容易把"高置信度的机制描述"误当成"已核实的一手引用"。

## 1. 调研问题

**核心问题：存储系统应当如何更好地服务大模型（LLM / 多模态基础模型）？**

这个问题在 2022 年之前几乎不存在独立的学术共同体：大模型训练被视为"计算 + 网络"问题，存储只是数据加载的配角。2023 年之后，三件事同时发生，使存储成为一等公民：

1. **KV Cache 的体积超过了模型权重本身**。以 70B 级模型、128K 上下文、batch=32 为例，KV Cache 可达数百 GB 到 TB 级，且随上下文长度线性增长，而 HBM 容量增长远慢于算力增长。推理系统第一次出现"算得完、放不下"的困境。
2. **Prefill/Decode 解耦与 PD 分离**把 KV Cache 变成了需要在集群内**搬运、复用、共享**的一等数据对象，催生了以 KVCache 为中心的架构（Mooncake 等）。
3. **训练侧的"存储墙"**在千卡/万卡集群上显现：checkpoint 风暴、小文件随机读、数据加载的元数据压力，使 GPU 利用率被存储拖累。

因此，本报告把"存储服务大模型"定义为：

> **围绕基础模型全生命周期（数据准备 → 预训练 → 后训练 → 模型分发 → 在线推理 → 多轮/Agent → 评估），为容量、带宽、延迟、元数据、一致性、隔离、持久化、数据移动、成本与能耗等存储职能提供系统级支撑的理论、技术与工程实践。**

它既包括**经典存储系统问题的新形态**（文件系统、缓存、分层、索引、checkpoint），也包括**因大模型而新出现的问题**（KV Cache 生命周期管理、语义缓存、Agent 记忆、前缀复用的一致性）。

### 1.1 术语约定

- 统一写 **KV Cache**（论文标题中的 KVCache 保留原样）；
- 统一写 **PD 分离**（prefill/decode disaggregation），不用“PD 解耦”作为同义替换；
- 统一写 **卸载（offload）**；
- 统一写 **前缀复用 / 非前缀复用**，与“缓存命中”区分。

### 明确排除的范围

- 纯模型算法（如新的注意力机制本身），除非它直接改变存储需求模型；
- 纯 GPU 算子优化（如 FlashAttention 的 kernel 实现），除非涉及 I/O 或存储层次；
- 纯网络协议栈研究，除非与存储数据移动耦合（如 RDMA 传输引擎、NVMe-oF）；
- 商业产品的营销材料，除非有可验证的架构或性能数字。

## 2. 证据来源、等级与核验方式

### 2.1 检索环境（2026-11-02 实测）

本会话的客户端搜索工具（WebSearch / WebFetch）被策略拦截，但 **shell 外网可用**。因此本次调研没有依赖模型记忆，而是直接调用官方 API 做真实检索：

| 来源 | 方式 | 规模 / 结果 |
|---|---|---|
| **arXiv 官方 API** | `export.arxiv.org/api/query`，47 组查询，覆盖 15 个子方向 + 按提交日期的最新扫描 | **1,878 篇去重论文**，最新 **2026-10-30**；被引集合最早 2016，抓取集合最早 1995（含宽查询噪声） |
| **GitHub API / raw** | 官方 README 与设计文档 | Mooncake、LMCache、SGLang、vLLM 等 |
| **OpenAlex / Crossref** | 备用元数据源 | 部分可用；DBLP 有反爬，Semantic Scholar 限流 |
| **CNKI / 万方** | 不可访问（需登录/反爬） | 国内期刊覆盖为本报告的主要缺口 |

arXiv 检索结果以 API 返回的**真实标题、摘要、发布日期、arXiv ID** 为准；所有综述章节只能引用抓取集合中实际存在的条目，引用格式统一为 `[arXiv:ID]`，并经过脚本核验（见 `tools/verify_citations.py`）。

### 2.2 三级证据等级

| 等级 | 含义 | 使用建议 |
|---|---|---|
| **A（API 实测）** | 标题、摘要、日期、ID 均来自 arXiv API，可复现 | 可直接引用；数字以摘要原文为准 |
| **B（官方文档）** | 来自项目 README / 官方博客 / 技术报告，可能随版本变化 | 引用时注明版本与日期 |
| **C（内部知识）** | 未出现在本次 API 结果中的背景判断（如某些会议的录用信息、厂商未公开细节） | 仅作背景，投稿/采购前必须回原始论文核实 |

**会议与年份**：arXiv 条目不等于顶会录用。本报告凡写"FAST 2025 / OSDI 2024"等，均来自官方 README 或模型内部知识，属于 **B/C 级**；写作时优先使用"arXiv 预印本 + 日期"，避免把预印本冒充顶会论文。

### 2.3 量化数字的处理

本报告中的性能数字分三类，阅读时必须区分：

1. **论文声称值**：原样引用摘要，标注"论文声称"，不跨论文比较；
2. **官方文档值**：注明来源与测试口径（如 Mooncake README 的 87 GB/s @ 4×200 Gbps RoCE）；
3. **本报告推导值**：来自 `analysis-quant.md` 的一阶模型，标注假设，仅用于数量级论证。

不同论文的 baseline、硬件、负载差异极大，**跨论文直接比较加速比是没有意义的**。

### 2.4 交叉核验

除 API 核验外，工作流中还包含两轮独立复核：

1. **内部知识交叉核验**：每条文献由"文献计量视角"与"技术主张视角"两个 agent 独立复核，用于发现年份、机构、机制描述的冲突；
2. **引用 ID 脚本核验**：所有综述中出现的 `[arXiv:ID]` 逐一比对抓取集合，缺失项会被标记（见 `05-参考文献与索引.md` 的核验栏）。

即便如此，**任何用于论文投稿、采购决策或对外发布的引用，都必须回到原始论文/官方文档核对**。

## 3. 分析框架

本报告采用"三层漏斗"：

```
第一层：文献层（What exists）
  ├─ 15 个子方向的系统性检索
  ├─ 按"生命周期阶段 × 存储职能"二维分类
  └─ 交叉核验与置信度分级

第二层：机制层（How it works, Why it fails）
  ├─ 提炼研究簇与技术演进脉络
  ├─ 识别每个工作的隐含假设
  ├─ 分析算法假设与存储假设的冲突
  └─ 定量模型：容量/带宽/成本/checkpoint/数据供给

第三层：方案层（What to do next）
  ├─ 缺口分析（真正未解决的问题）
  ├─ 研究方案生成（多方案独立提出 + 评审）
  └─ 可行性、风险、评测设计
```

### 二维分类框架

- **横轴：大模型生命周期阶段**
  数据准备 / 预训练 / 后训练与对齐 / 模型分发 / 在线推理 Prefill / 在线推理 Decode / 多轮对话与 Agent / 评估与可观测

- **纵轴：存储系统职能**
  容量 / 带宽 / 延迟 / 元数据 / 一致性 / 隔离与安全 / 持久化 / 数据移动 / 成本与能耗

这个框架的价值在于暴露**空白格**：例如"Agent 阶段 × 一致性"、"Prefill 阶段 × 隔离"、"后训练 × 成本"等组合，目前几乎没有系统研究。

## 4. 与既有综述的差异

已有综述大致分三类，本报告试图补足它们的盲区：

| 既有综述类型 | 代表视角 | 盲区 |
|---|---|---|
| KV Cache 压缩综述 | 算法视角（token 选择、量化） | 不讨论存储层次、复用一致性、集群调度 |
| LLM 推理系统综述 | 系统视角（调度、并行、PD 分离） | 把存储当作"内存不够就 offload"的黑盒 |
| 存储系统综述 | 传统存储视角（文件系统、对象存储） | 不覆盖 KV Cache、语义缓存、Agent 记忆等新对象 |

本报告的定位是**跨层**：把"算法产生的数据形态"与"存储系统的管理粒度"放在同一个框架里讨论，并明确指出二者的假设冲突。这是我们认为最有研究价值的地方，也是 `04-研究方案提案.md` 的主要来源。

## 6. 已知局限

1. **检索源偏差**：本次以 arXiv API 为主。部分顶会论文（如 3FS、OceanStor 相关系统）没有 arXiv 版本；部分工业工作完全不公开。因此"某方向论文数量"只能反映 arXiv 活跃度，不能等同于领域全貌。
2. **时间边界**：检索截止 **2026-10-30**；此后发表的工作不在覆盖范围内。
3. **会议/年份未逐一核实**：arXiv 元数据不含录用信息；报告中的 FAST/OSDI/SOSP 等标注来自官方 README 或内部知识，属 B/C 级证据，引用前需用 DBLP 核对。
4. **工业界数据口径不一**：厂商博客通常缺少 baseline、负载与硬件说明；报告尽量标注"官方口径"，但跨厂商数字不可直接比较。
5. **中文文献覆盖不足**：CNKI、万方不可访问；国内期刊（《计算机学报》《软件学报》《计算机研究与发展》）与 CNCC 报告覆盖弱，是国内团队成果的主要遗漏来源。
6. **定量模型是一阶近似**：用于数量级论证，不作为精确预测；所有假设写在 `raw/analysis-quant.md` 中。
7. **LLM 生成内容的固有风险**：综述章节由检索增强的 agent 撰写，虽经 ID 核验与交叉复核，仍可能存在机制描述偏差；关键结论请以原始摘要为准。
